# DEC-069: worktree 生命周期硬约束 —— 上限、登记、必删

> 事故：一天之内本地累积到 **12 个 worktree**，没有任何机制阻止继续创建；
> 用户发现并要求清理后才降下来。决策：把"不要堆积"从提醒变成**机器强制**。

## 规则

| 规则 | 机制 | 违反时 |
|---|---|---|
| 任务 worktree 上限 3（可 `WF_WORKTREE_LIMIT` 调整） | `ses-worktree.sh add` 守卫 | 拒绝创建，打印清理命令 |
| 临时突破 | `--force` | 显式承担 |
| 创建即登记 | 追加 `.cache/worktrees.jsonl`（分支/时间/会话） | 供 doctor 审计年龄 |
| 合入即删 | `wf-queue.sh` 合入后删除分支与 worktree | — |
| 队列候选必删 | `trap cleanup_candidate EXIT INT TERM` | 被 kill 也不留目录 |
| 会话结束兜底 | `ses-session-end` → `gov-workspace-doctor --fix` | 清理已合入/孤儿 |
| 审计 | `gov-workspace-doctor`（已合入、孤儿目录、过期锁） | WARN/FAIL |

## 为什么是硬上限而不是提醒

实测：提醒类规则（AGENTS.md 里写"用完即删"）在高压会话里 100% 失效；
而"第 4 个创建请求被拒绝"是**不可忽略**的信号，且自带解法提示。

## 顺带修正

全量车道从 `gradlew build` 改为 `gradlew test`（编译 + 全部单测），
打包/lint/release 对合入判断没有增量信号，却占 3~5 倍时间；
发布前需要完整构建时用 `GOV_CI_PROFILE=build`。
