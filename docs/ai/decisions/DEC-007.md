# DEC-007: 进程内 pytest 夹具吞掉校验现场 — FAIL 打印了但违规计 0

> 根因：pytest.main 进程内执行 + 每测试 core.errors.clear()，把 pytest 阶段之前累积的全部违规清零；夹具改快照-恢复，配元测试锁住。

---

## 决策

实现 DEC-006 的 GOV-README 规则时观察到自相矛盾的输出：GOV-README-001 明明
打印了 `[FAIL]`，摘要却是 `违规: 0 项`、退出码 0。追查发现一条链上的第三个缺陷
（前两个：DEC-004 R0 比对基线、DEC-005 输出契约）：

- `gov_validate_tests.check_pytest` 用 `pytest.main()` **在 validate 自己的进程内**
  执行测试套件（GOV-TEST-005）；
- `test_governance_negative.py` 的 autouse 夹具 `_clean_errors` 在**每个测试前后**
  `core.errors.clear()`，清的是与宿主进程共享的同一个列表对象；
- 结果：**pytest 阶段之前所有规则收集的违规（R0、GOV-README、GOV-STRUCT、
  GOV-CONTENT、GOV-PROTO、GOV-SCRIPT 全部）在全量模式（非 QUICK）下被静默清零**，
  摘要与退出码均显示通过。CI docs-validate 跑的正是全量模式——此前的"全绿"
  对早期规则是假阳性；pre-commit 因 QUICK 跳过 pytest 才侥幸不受影响。

修复：

1. **夹具改快照-恢复**：进入测试时快照 `core.errors` 并清空（保持测试隔离），
   测试结束后恢复快照。测试自己制造的错误仍被清理，宿主进程现场错误幸存。
   独立 pytest 运行时快照为空，行为与原来一致——零迁移成本。
2. **元测试** `test_clean_errors_fixture_preserves_outer_errors`：手动驱动夹具
   生成器，断言外部现场错误在测试结束后仍在列表中。
3. 不改 `pytest.main` 的进程内执行方式：换子进程会影响输出捕获与耗时，
   夹具的语义修正已足够，且更小的变更面更可验证。
