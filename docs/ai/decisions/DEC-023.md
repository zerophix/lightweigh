# DEC-023: Android 治理本地化收口

> 判定本套治理可按语言耦合度分层落地于 Android 项目，明确已适配与待适配缺口，并以 CI 对齐、Android 测试治理、analyzer 修整三件闭环。

---

## 决策

评估确认：这套治理并非"Python 项目的治理"，而是"以 Python 实现的治理引擎"。按语言耦合度分
四层，落地策略逐层不同：

1. **协议层**（AGENTS.md、docs 结构、DEC/NOTE/GC/REF 命名、10 步生命周期、评审、接力）零
   语言耦合，已全量生效，无需改动。
2. **门禁层**（pre-commit/commit-msg/pre-push）零语言耦合，`SRC_DIRS` 已配置为四个 Gradle
   模块。但 CI 侧已与治理脱钩：`.github/workflows/ci.yml` 仅剩 `build-and-guard`（跑 Gradle
   构建与 ArchUnit），而 AGENTS.md 仍承诺 `docs-validate`/`lifecycle-audit`/`docs-build`/
   `deploy` 四个 job——文档与实现漂移，治理门禁实际只剩本机 hooks，`--no-verify` 后无 CI
   兜底。
3. **引擎层**（gov-validate.py 与校验模块）实现语言是 Python，但校验对象是文档、脚本与测试
   目录，因此对 Android 工程可移植。残留两处 Python 形状假设：测试治理层与 R0d 依赖目录
   白名单。
4. **指标层**已通过 metrics-hooks/00-document.sh 全量替换为 Kotlin/Java/Gradle 口径，项目
   自有目录不受升级覆盖，无需改动。

待适配缺口与处置：

- **CI 对齐**：二选一，ci.yml 补 docs-validate job，或改 AGENTS.md 去除已不存在的 CI 承诺，
  必须二处一致。
- **Android 单元测试治理**：现有 GOV-TEST 族硬编码 `tests/` 目录与 pytest 文件命名
  （`^test_[a-z0-9_]+\.py$`），治理的是治理自身的 pytest 套件，完全不覆盖
  `domain/application/infrastructure/app` 的 `src/test` 下的 Kotlin/Java 测试。新增
  `gov_validate_android_tests.py` 镜像同一套规则：扫描各模块 `src/test` 与 `src/androidTest`
  的 `*.kt`/`*.java`，校验文件名（PascalCase 且以 Test 结尾）、禁止版本/备份命名、禁止 emoji、
  注册表反向校验。遵守先写负向测试再写实现的约束。
- **analyzer 修整**：scripts/registry.yaml 注册的六个分析器
  （tools/analyze/ana-fs-*.py、ana-similarity.py、tools/metrics/ana-metrics-*.sh）磁盘上不
  存在，是僵尸条目；且 GOV-SCRIPT 缺少 registry 完整性/反向校验（tests 侧有镜像
  GOV-TEST-GOV-001/005）。处置为补回分析器或删条目，并补 GOV-SCRIPT 的 registry 校验。
- **R0d 白名单**：依赖目录白名单是 Python/Node 形状，Gradle 产物与缓存目录
  （build/ .gradle/ .kotlin/ .idea/）不被治理，属"盲而不报"。处置为补入白名单或声明为治理
  盲点。
- **引擎层工具链**：gov-validate 依赖 Python 3.9 以上与 pytest。对 Android 团队这是额外前置
  依赖，建议保留 Python 引擎（现成、可移植），并明确 Python 只服务治理与文档站、不服务
  Android 构建的边界。
