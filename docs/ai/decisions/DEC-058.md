# DEC-058: CI 变更范围白名单扩展，非构建类路径不再触发重型构建

> 治理、测试、原型、skill 的改动与 Kotlin 编译无关，却每次白跑全量 gradle 构建；把分类逻辑抽为可测单一真源，并在保证「不漏源码」的前提下扩白名单。

---

## 决策

### 问题（实测）

`ci.yml` 原内联判定只认 `docs/` 与 `*.md`：

```bash
grep -qvE '^(docs/|\.ai/|\.cache/|mkdocs\.yml$|.*\.md$)'
```

PR #31 中 24 个文件因此被判 `code=true` 触发全量构建，其中**零个** Kotlin / gradle 源：

| 类别 | 数量 | 是否参与 gradle 编译 |
|------|:----:|:-------------------:|
| `design/prototypes/**/*.html` | 12 | 否 |
| `scripts/governance/*.py` | 5 | 否 |
| `tests/unit/*.py` | 3 | 否（`pytest.ini testpaths=tests`） |
| `.opencode/skills/*.yaml` | 4 | 否 |

放大因素：`pull_request` 事件以 `merge-base(master)` 为基线（整条分支），故**开 PR 几乎必然**触发重型构建；而 `push` 事件以上次 push 为基线（文件少），两者耗时严重不对称。

### 决策内容

1. **分类逻辑抽为单一真源** `scripts/governance/gov-ci-scope.sh`，`ci.yml` 只做基线解析后调用它。理由：内联在 workflow 里的正则无法被 pytest 覆盖，改白名单时无人能验证「会不会漏掉源码」。
2. **白名单扩展**至 `design/`、`scripts/`、`tests/`、`.opencode/`、`.claude/`（保留 `docs/`、`.ai/`、`.cache/`、`*.md`、`mkdocs.yml`）。
3. **保持白名单而非黑名单**：只有全部变更落在白名单内才跳过构建。gradle 模块固定为 `app / application / domain / infrastructure` 加根部构建脚本，均不在白名单内，故动到任一源码必判 `code=true`。扩白名单只消假阳性，不产生假阴性。
4. **`.github/` 不入白名单**：改 CI 配置本身仍保守触发构建（一次成本，换取 CI 自身变更被真实执行验证）。
5. **保守分支收紧**：原逻辑对空 diff 判 `code=false`（可能因 diff 静默失败而跳过门禁），改为 `code=true`。
6. **`docs-validate` 不受 scope 门控**（`if` 条件仅在 `build-and-guard` 的三步），故跳过构建时 `gov-validate` 与 pytest 仍执行，门禁不空缺。

### 明确不动的

- 不改 `on.push` 触发分支 —— DEC-049 要求特性分支 push 也跑 CI。
- 不动已有 `concurrency`（`cancel-in-progress` 对非 master 生效，DEC-033）。
- 不调 gradle 缓存策略 —— `GRADLE_USER_HOME` 落项目内 `.gradle-user` 是 DEC-033 的实验假设，不在此混改。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 白名单外必然含 gradle 源，故不产生假阴性 | 新增构建类目录时同步改白名单 | 源码变更被跳过，门禁空缺 | 已验证（5 类源码用例均 code=true） |
| A2 | `scripts/`、`tests/`、`design/` 不被任何 gradle 文件引用 | 构建脚本不引入这些路径 | 构建行为漂移却未验证 | 已验证（grep 4 类 gradle 配置零引用） |
| A3 | 跳过构建时 `gov-validate` 仍执行 | `docs-validate` 无 scope 门控 | 治理校验被连带跳过 | 已验证（该 job 无 `if:` 条件） |
| A4 | 混合变更中任一源码即触发构建 | 白名单为「全部命中才跳过」 | 半个 PR 漏构建 | 已验证（混合用例 code=true） |
| A5 | 改白名单须同步改测试 | 测试是唯一回归防线 | 白名单被随意放宽 | 由 15 条测试守护，写进 ci.yml 注释 |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 抽为脚本 + pytest 守护（采纳） | 5/5 | 单一真源、可测、可本地复现；ci.yml 变薄 |
| 只改 ci.yml 内联正则 | 2/5 | 无法测；改白名单时「会不会漏源码」无人回答 |
| 反转为黑名单（默认跳过） | 1/5 | 新增构建目录即漏检，违背「宁可多跑不留空洞」 |
| 干脆取消重型构建门禁 | 1/5 | 与 DEC-049「构建当门禁」意图相反 |
