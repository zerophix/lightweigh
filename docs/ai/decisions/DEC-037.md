# DEC-037: T-016 仓储接口读写分离（查询端口归 application，实现在 infrastructure）

> domain 仓储接口仅存取（save/delete），recent/between 迁移为 application 层查询端口 `MeasurementQueryPort`/`HealthLogQueryPort`，由 infrastructure 实现，读模型类与查询服务改依赖端口。

---

## 决策

T-016 仓储接口精简的落位方案：

1. **domain 仓储纯写口**：`MeasurementRepository` 仅 `save/delete`，`HealthLogRepository` 仅 `save`——`recent/between` 从领域端口移除，满足「domain.repository 仅存取」的任务目标。
2. **查询端口定义在 application**（`MeasurementQueryPort`/`HealthLogQueryPort`），照既有先例 `SyncStatePort`/`BlePort`/`AiPort`——这些端口同样定义在 application、由 infrastructure 实现（`RoomSyncStateRepository`/`AndroidBleLink` 先例），`infrastructure` 的 gradle 依赖已含 `application`。
3. **查询实现位于 infrastructure**：`RoomMeasurementQuery`/`RoomHealthLogQuery` 直走 DAO（保留按成员过滤语义）；`InMemory*Repository` 双实现写口+查询端口（测试/演示共用一个实例即无「写读不同实例」问题）。
4. **读模型类保持原名**：`MeasurementQuery`/`HealthLogQuery`（含 `HealthLogItem` 格式化）不改签名形态，仅构造参数从仓储改为端口——`MeasureViewModel` 与 UI 层零改动。
5. **组合根提供两个查询属性**：`measurementQueryPort`/`healthLogQueryPort`（给 Trend/History/Report/HomeGoal/SyncService），`measurementQuery`/`healthLogQuery`（读模型壳，给 ViewModel）。ArchUnit「AppContainer 公开属性不得暴露 infra 具体类型」对返回 application 端口类型放行，守卫保持绿色。

被否决的中间方案：在 `domain.repository` 新增 `MeasurementQuerySupport(recent/between, memberId)`——它把查询方法换名塞回了 domain 仓储包，违背 T-016 自身目标；且需要 application 再包一层 `*QueryImpl` 委托链（接口→Impl→Support→仓储）共 4 层样板。该方案在实现中途被架构对照检查发现并整体回退（半天工作量教训：先对齐先例再动手）。
