# DEC-063: 流程解耦 —— 重检查移到里程碑，快检查留给手指

> 写代码时 git 操作应零等待；只在「开 PR」与「session 边界」两个时刻付一次流程成本。
> 把 161 条 pytest 挂在每次 push 上没有增加任何安全性——合入门禁从来都是 local-ci。

---

## 背景（实测证据，2026-10-24 分支推进日）

| 摩耗 | 当日实测 |
|------|----------|
| Gradle 冷构建 | 新 worktree 首次 local-ci ~6 分钟 |
| 同一检查重复执行 | pytest 在 pre-commit/pre-push/local-ci 跑 3+ 遍 |
| GOV-DOCS-004 计数 | 6 分支各存一份计数副本，合并后逐分支手动重算 5 轮 |
| 墙钟门禁误伤 | `git push --delete` 清理已合并分支被 inbox 48h 未读拦截 |
| 双 agent 重复实现 | cursor #39/#40/#41/#43 与本方分支功能重复，产出废弃近半 |

结论：**流程成本已超过代码成本**。重检查（pytest/全量 build）挂错在高频动作（push）上，
真正的合入门禁（local-ci，DEC-048）反而只在低频时刻执行一次。

## 决策

### A. GOV-DOCS-004 计数校验改主干作用域

- `_check_counts` 失配时先问 git 当前分支：`feat|fix|docs|refactor|chore|test|ci/*` → **降级 WARN**
- master / main / HEAD（CI detached 检出）/ 非 git 目录 / git 不可用 → **仍 ERROR**
- git 不可用时保守降级为主干语义（守门强度只增不减）
- 守门位置不变：local-ci 在 master 语义下跑，合入前仍然全绿才放行

### B. 墙钟门禁豁免零代码动作

- pre-push 钩子读取 refspec：全删除（local sha 全 0）或空 refspec → `export GOV_SKIP_WALLCLOCK=1`
- 该变量**仅**豁免 GOV-PROTO-001/002（收件箱 48h / session-end 24h）
- GOV-PROTO-003/004（僵尸任务 / AC DoD）**不受影响**，照常执行
- session-end / local-ci 不注入该变量，接力铁律在里程碑处仍强制

### C. pytest 全量执行移到 local-ci

- pre-push `export GOV_VALIDATE_QUICK=1`（复用 DEC-062 已有的 QUICK 开关）
- push 只做：分支命名 + 文档校验（秒级）+ 密钥扫描
- 161 条 pytest 只在 local-ci（合入门禁，DEC-048）执行——与「合入权威 = local-ci」的既有分工对齐
- `.ai/staged-claims.json` 不入库（已 git rm --cached）：多分支共享同一份 claims 副本
  只制造 add/add 冲突，归属声明本来就是本机会话行为

### D. 合并后一键同步 + Gradle 并行

- 新增 `scripts/governance/gov-board-sync.sh`：`gov-validate --fix` + 有变更自动提交
  （原 5 轮手动重算 → 0 轮）
- `gradle.properties` 加 `org.gradle.parallel=true`（缓存 `org.gradle.caching=true`
  已有，DEC-033）

## 明确不动的

- local-ci 六步全绿仍是合入门禁（DEC-048）——**放松的全部是 push/commit 层，合入层零放松**
- `--no-verify` 仍是任务禁令
- 密钥扫描在 push 层保留（秒级、事后修贵）
- 墙钟豁免不扩展到普通 push——只放行纯删除/空 refspec

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 特性分支计数失配会在合入时被 master 语义抓到 | local-ci 必跑且在主干语义下 | 计数脱节漏到 master | 已验证（4 条单测覆盖特性/主干/detached/非 git） |
| A2 | 全删除 refspec 的 local sha 全 0 | git 标准行为 | 误豁免普通 push | 已验证（git 标准，hook 内 case 匹配 `*[!0]*` 反证） |
| A3 | QUICK 只跳 pytest，不跳文档/密钥/schema 校验 | gov_validate_tests.py 实现 | 豁免面扩大 | 已验证（DEC-062 引入时已测） |
| A4 | claims 本地化不影响归属守卫 | pre-commit 读本地文件不依赖其被跟踪 | 多会话归属失效 | 已验证（钩子读文件内容，与 git 跟踪无关） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 分层解耦：重检查移 PR/session 边界（采纳） | 5/5 | 安全强度不降（合入门禁原样），砍掉的全是重复执行 |
| 全部门禁降为 local-ci 一道 | 2/5 | push 层密钥扫描等秒级检查也丢失，事后修贵 |
| 维持现状 | 1/5 | 当日实测：流程成本已超过代码成本，多 agent 并行被拖垮 |

## 生效方式

钩子是安装副本：合入后各机器运行 `bash scripts/bootstrap/bs-install-hooks.sh` 刷新。
仓库内 `scripts/governance/gov-pre-push` 是唯一真源（DEC-047 分工不变）。
