# DEC-064: 开发与质量控制解耦，并发以任务为单位

> 2026-10-24 实测：一天 9 个 PR，真正新增产品代码只有 1 个；流程耗时占 60~70%。
> 根因不是某条规则，是"按动作设卡 + 用 git 共享文档协调 + 规则只增不减"的组合。

---

## 问题（实测证据）

| 现象 | 当日数据 |
|------|----------|
| 多 agent 重复实现 | cursor 家族 4 个 PR 与本方功能重复，全部废弃 |
| 合并冲突 | 5 轮，全部来自 `.ai/tasks.json` / 计数文档 / STATUS 等共享文件，**0 轮来自真实代码** |
| 门禁误伤 | worktree 假阳性拦死全部分支提交（DEC-062）、墙钟拦 `push --delete`、归属钩子静默拒提交导致一次 merge 白做 |
| 重复执行 | pytest 3 遍/变更、全量 gradle 每次 local-ci（冷启动 6 分钟） |
| 同坑三踩 | 新 worktree 缺 `local.properties` 三次才修工具 |
| 规则只增 | 63 条 DEC 仅退役 1 条；治理自身已成第二个待维护产品 |

## 决策

### 1. 快慢两层（解耦核心）

- **快层（commit/push）**：分支名 + 禁 master + 密钥扫描 + 文档校验。秒级，不跑 pytest、不跑全量构建。
- **慢层（PR/合入）**：`gov-local-ci.sh` 全绿为唯一合入权威（沿用 DEC-048），按车道决定深度。
- 编码期间不因流程停下：认领 → 写代码 → 跑相关单测 → 提交推送。

### 2. 风险车道（A/B/C）

按变更路径自动判定，复用 `gov-ci-scope.sh` 分类：

| 车道 | 触发 | 门禁 |
|------|------|------|
| A | 非构建路径（docs/design/scripts/tests/.ai 等） | 不跑 gradle，文档/密钥/schema/test-guard 照常 |
| B | `app/src/**` | `:app:testDebugUnitTest` + 其余步骤 |
| C | domain/application/infrastructure/golden/schemas/构建文件/未知路径 | 全量 `gradlew build` |

混合取最高；`GOV_LANE=full` 强制全量；检测失败按 C。

### 3. 共享文件单一写者

`.ai/tasks.json`、`03_TaskGraph.md`、`STATUS.md`、`android-test-registry.yaml`、`06_Metrics.md` **只由合并队列/收尾自动化写**；功能分支只提交自己的代码与测试。并发冲突从机制上消除。

### 4. 任务级并发 + 原子锁

- 并发单元 = 任务（T-xxx）= 分支 = worktree = 锁。
- `wf-claim.sh claim <ID>`：`mkdir .ai/locks/<ID>` 原子抢锁，失败即换任务；TTL 24h；`gc` 清理。
- pre-commit 命中他人锁的 `target_files` 时拒绝提交（锁不存在不拦，渐进收紧）。
- 分支寿命 < 1 天，超时先 rebase。

### 5. 合并队列

`gov-merge.sh <PR>`：拉 master → 冲突则停（交人）→ 派生物同步 → local-ci → 合入 → 删分支/worktree。替代 5 轮手工解冲突。

### 6. 派生数据不手写

任务计数、测试清单、状态摘要一律从真源生成或直接引用。`03_TaskGraph.md` 不再手写计数，**GOV-DOCS-004 退役**。

### 7. 墙钟门禁退役

GOV-PROTO-001/002（inbox 48h / session-end 24h）不保护任何产物，只按时间惩罚行为 → 退役。接力信仍写、仍读，但不拦任何 git 操作。GOV-PROTO-003/004（僵尸任务 / AC DoD）保留——它们保护任务板真实性。

### 8. 规则生命周期

新门禁的 DEC 必须写清：**保护指标 / 预期成本 / 复审条件**。两次误伤或 30 天零命中 → 退役评审。规则净增速不得超过产品决策增速。

### 9. 执行纪律（写进 AGENTS.md）

- >10 秒的命令一律后台或交子代理，不阻塞主流程。
- 相互独立的任务用子代理并行（各一 worktree），主线程只做评审与合并。
- 同工作区禁止并行跑两个校验器。

## 明确不动的

- local-ci 全绿仍是合入硬门槛；`--no-verify` 仍禁。
- 密钥扫描、schema guard、原型文案 `--strict`、AC DoD 检查全部保留。
- 无 GitHub Pro / 无分支保护的现实不变；CI 账单修复后可进一步把重门禁搬到平台层（另议）。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 按路径能把变更归入 A/B/C 且混合取最高是安全的 | 构建依赖只来自源码/配置路径 | 漏跑全量构建导致编译问题晚发现 | 已验证（29 条车道单测，含未知路径→C） |
| A2 | 原子目录锁足以阻止重复实现 | 所有 agent 遵守"先 claim 再开工" | 无锁的 agent 仍可重复做 | 已验证（16 条锁单测含并发抢锁）；纪律靠 AGENTS.md 约束 |
| A3 | 共享文件单一写者能消除合并冲突 | 合并队列覆盖所有合入路径 | 有人绕过队列直接改共享文件 | 部分验证（本轮 7 个 PR 合并将复核冲突数） |
| A4 | 墙钟规则删除不影响交接质量 | 交接内容本身可读、可执行 | 交接变敷衍 | 观察项：下个会话按交接内容能否独立开工 |
| A5 | 计数不再手写不影响可读性 | 读者能查 `tasks.json` | 文档读者体验下降 | 观察项 |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 快慢分层 + 车道 + 单一写者 + 任务级锁 + 合并队列（采纳） | 5/5 | 安全强度不降（合入门禁原样），砍掉的都是重复执行与自造冲突 |
| 继续逐条修规则（DEC-063 路线） | 2/5 | 治标：每次只消一个冲突源，规则总数继续增长 |
| 取消全部本地门禁，只靠人审 | 1/5 | 无分支保护时等于无守门，与 DEC-048 冲突 |

## 来源: 2026-10-24 六分支合入日复盘；人类要求"代码开发与质量控制解耦、并发推进"。
