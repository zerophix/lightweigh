# DEC-013: 未填充的决策模板纳入 GOV-CONTENT 校验

> 给决策日志加一道「拒绝空模板入库」的校验：GOV-CONTENT-012 用白名单匹配
> gov-next-decision.sh 模板的占位 token，未填充的 DEC 一律 FAIL。

---

## 背景

DEC-012 事故：`gov-next-decision.sh --create` 在并发会话占用编号的瞬间分配了 DEC-012，
生成的空模板被另一次提交误扫入库，决策日志里出现了一份没有任何真实内容的占位决策
（标题与正文都是模板占位串：决策标题、一句话描述、决策内容、第 N 步待办、关联文件、
假设、方案 A / 方案 B、理由、触发条件）。

根因是**校验盲区**，不是操作失误：

- GOV-CONTENT-004（check_decisions）只检查编号连续性，从不读内容；
- 唯一会检查占位符的 `gov-validate-decisions.sh` 虽在 registry 中注册，却**没有被
  pre-commit 或 gov-validate.sh 调用**——是一段死代码。

于是空模板在所有门禁下畅通无阻。同类问题见 NOTE-20261014-002 摩擦点 #3
（另一分叉的 DEC-217 未填充占位）。

## 决策

- 新增 **GOV-CONTENT-012「决策模板占位符」**：扫描全部 `docs/ai/decisions/DEC-*.md`，
  命中模板占位 token 即 FAIL（拒绝入库）。
- 判定用**模板 token 白名单**，不用通用 `<...>` 正则。理由：DEC-010 正文合法地使用
  `<源>` 这类尖括号，通用正则会误报——治理笔记「含尖括号即占位」的原始建议会造成假阳性。
- 单一事实源：白名单对应 `gov-next-decision.sh` 的模板；新增
  `test_placeholder_list_covers_template` 断言白名单覆盖模板全部尖括号 token，二者不允许漂移。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 空模板会命中白名单 token | 模板 token 稳定 | 规则漏检 | 已验证（DEC-013 空模板实测 FAIL） |
| A2 | 合法 DEC 不误报 | 白名单足够精确 | 误伤正常决策 | 已验证（DEC-010 的尖括号不触发） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 模板 token 白名单（采纳） | 5/5 | 精确、可做漂移检测、零误报 |
| 通用尖括号正则 | 2/5 | 实现最简，但 DEC-010 的 `<源>` 直接误报 |
| 仅接线现成的 gov-validate-decisions.sh | 3/5 | 复用已有脚本，但只查 staged 文件的标题，覆盖弱 |

## 影响面

- `scripts/governance/modules/gov_validate_content.py`（上游拥有区）：新增白名单 + 校验函数，
  并接入 `check_all()`。该文件在 `gov-owned.list` 内，属**对上游基线的有意分叉**：
  后续 `gov-upgrade.sh --check` 会报告此差异，应把它作为模板侧改进回推上游后再收敛。
- `tests/unit/test_governance_negative.py`：+4 用例（负向、正向、合法尖括号防误报、白名单漂移）。
