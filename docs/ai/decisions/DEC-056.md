# DEC-056: 扫描回调 deviceName 参与 Chipsea 混合协议识别

> 补齐 DEC-044：仅靠 AD 0x09 不够——真机 Chipsea_BLE 常把名称只放在 `BluetoothDevice.getName()`，scanRecord 无 Complete Local Name，仍被误判为 okok-1。

---

## 决策

在 `Protocols.match` / `ChipseaCloudProtocol.match` 增加可选 `deviceName` 参数；`isChipseaName` **优先**用该参数（不区分大小写包含 `chipsea`），否则再解析 AD 0x08/0x09。

调用方：

- `DeviceViewModel.onDeviceFound` → `Protocols.match(scanRecord, name)`
- `MeasureSession` 识别与 `preferAdvertisedProtocol` → 传入扫描回调 `name`

`AndroidBleLink` 已把 `device.name`（空则 `scanRecord.deviceName`）交给监听器，本决策不改链路层。

不改 `applicationId` / 包名。

## Assumptions

| ID | 假设 | 失败影响 | 验证 |
|----|------|----------|------|
| A1 | 扫描回调 name 对 Chipsea_BLE 含 Chipsea | 仍误判 OKOK | NOTE-20261021-001 / 真机日志 |
| A2 | 纯 OKOK 名称不含 Chipsea | 误伤 OKOK | 既有 OKOK-SCALE 测试 |
| A3 | 无 name 时行为与 DEC-044 一致 | 回归 | 单测：无 name 的 0x10 → okok-1 |
