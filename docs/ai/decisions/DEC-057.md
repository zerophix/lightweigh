# DEC-057: 原型与文档治理从文档约束升级为脚本门禁

> GC 文档写了不等于被 AI 执行；把「必须遵守」改由 validator 脚本在三层闸门强制，并为可自洽验证的项开放 `--fix` 自愈。

---

## 决策

### 1. 强制力介质：validator 脚本，不用 AGENTS.md

治理设计约束 Q2 判定：AGENTS.md 规则最易写也最易被忽略。故新增规则一律进 `gov-validate.py` 模块，
随 pre-commit / gov-local-ci / GitHub Actions 三层闸门生效，违规返回非零阻断合入。

| 规则族 | 检查对象 |
|--------|----------|
| GOV-PROTO-001~007 | 任务板 `prototype_ref` / `target_files` / `wave` / `module` / `ac_refs` / `prd_ref` |
| GOV-DOCS-001~005 | 索引收录、相对链接可达、真源声明、摘要计数与任务板一致、入口文档时效 |

### 2. 自愈准入：只修「自洽」项，禁止「自噬」项

判断标准 —— **改错了会不会被同一条规则立刻抓到**：

- `--fix` 重写已有锚点（计数同步），改错则 004 下次仍红 → 允许自动修
- 时间戳 bump 属自噬：无脑改成今日会让 005 永久失效 → 必须绑定「内容相对 HEAD 有变更」，
  无法判定（非 git 仓库 / 无 HEAD）时保守不改
- 统一边界：**只重写已有锚点，不新增结构**；缺行、缺标记、缺索引条目一律留人工
- 不接 git hook，保持仓库既有约定：显式命令，人主动跑

### 3. `docs/reference/index.md` 不可手改

该文件自述「由 DEC 或生命周期文档晋升后写入」，故 GOV-DOCS-001 对 `REF-*` 未收录只报 WARN，
由 `wf-promote.sh` 消解，禁止为消警告直接编辑 index。

### 4. PR 模板必须 guard-safe

`gov-test-guard` 与 `gov-schema-guard` 靠匹配 PR body 关键词放行，模板若自带放行词面量或
`DEC-` 加三位数字，等于未填写也放行，门禁形同虚设。故模板刻意不含这些字面量，
并由 7 条测试锁住（变异验证：塞入即红）。

### 5. Skill 承载「怎么写对」，脚本承载「有没有写」

`.opencode/skills/prototype-dev` 与 `docs-manage` 负责流程、映射表与书写规范；
脚本只保证结构与数字。语义质量仍需人工评审 —— 两者不是二选一。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 把规则写进 validator 即被强制执行 | 三层闸门未被 `--no-verify` 绕过 | 回到文档约束，规则被静默忽略 | 已验证（违规 exit=1） |
| A2 | `git diff` 能可靠判定入口文档内容变更 | 工作区为 git 仓库且有 HEAD | 时间戳不再更新，005 持续提醒 | 已验证（3 种场景单测） |
| A3 | `SRC_DIRS` 不含 `scripts/`，治理变更无需 DevNotes | `gov-config.sh` 未改 | lifecycle-audit 误拦 | 已验证（audit exit=0） |
| A4 | 模板不含放行词即不会误放行 | 词面量不被后续编辑重新引入 | 门禁静默失效且无人察觉 | 已验证（变异测试抓到） |
| A5 | 计数锚点存在即可被 `--fix` 重写 | 摘要保持既有锚点句式 | 结构漂移，004 转红交人工 | 已验证（缺行用例仍红） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| validator 脚本进 gov-validate（采纳） | 5/5 | 三层闸门现成，加模块即生效；可测试、可阻断 |
| pre-commit 自动改写暂存文件 | 2/5 | 提交变得不可预期；仓库既有自动化也未走 hook |
| AGENTS.md / GC 文档写规则 | 1/5 | 最易写最易忽略，正是本决策要解决的问题 |
| 让 CI 调 Notion 做双向同步 | 1/5 | 引入外部依赖与凭据，CI 变慢且脆弱 |
