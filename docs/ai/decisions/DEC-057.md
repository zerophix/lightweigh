# DEC-057: 需求到编码链路作为任务验收锚点

> 并发实现必须引用 PRD、原型与 schema，并把上层验收抄进完成定义。上层变更时按下层 pin 级联。

---

## 决策

1. 新增 `docs/guides/GC-req-to-code-chain.md` 作为层级权威、追溯 ID、钉住与级联的短规范。产品行为指向 Notion 空间「轻衡健康」的标题（`PRD-产品需求`、`DOC-目录与命名规范`、`03-原型`）。链路页标题 `DOC-需求到编码链路` 只按标题引用：撰写时检索不到该正文，不编造 URL。
2. 扩展 `acceptance.refs`（`prd` / `schema` / `prototype` / `pin`）与 `dod_source`。完成定义从上层条款抄录。`n/a` 必须带理由。
3. `GOV-PROTO-005`：`status=in_progress` 或 `acceptance.status=ready` 缺上述字段则 FAIL。`pending` 且仍为 `draft` 只 WARN。`done` / `completed` 不查。现有看板无 ready、无 in_progress，合入不把历史任务打红。
4. `AGENTS.md`、编码约定、多 AI 协议、PR 模板与 Cursor/Cline 启动段各加短指针。不新开 `docs/governance/`：`GOV-STRUCT-004` 只允许 `docs/guides/GC-*.md`。

仓库 `DEC-xxx` 与 Notion 产品页 `DEC-*` 不是同一套编号。任务引用产品决策时写全标题。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 现有任务没有 ready / in_progress | `.ai/tasks.json` | 硬门禁误伤看板 | 撰写时检索确认 |
| A2 | 草案只警告不会被当成校验失败 | `fail()` 只收集硬错误 | 无 | 负向测试 |
| A3 | Notion 标题稳定，URL 不必入库 | 空间「轻衡健康」 | 标题改名后指针过期 | 引用标题而非猜测链接 |
