# DEC-073: 共享文件单一写者 —— 功能分支不能改派生数据

> 2026-10-24 反复出现: 同一个 PR 改了 `.ai/tasks.json`、另一个 PR 也改了、
> 合并后患者少数的计数不一致；再合并另一个冲突。
> 根因不是"改得不好"，而是"多人写同一文件"。

---

## 共享文件清单（唯一写者: 合并队列/收尾）

| 文件 | 真正写入权限 | 功能分支是否允许 |
|---|---|---|
| `.ai/tasks.json` | `wf-queue.sh` + `ses-session-end.sh` | ❌ |
| `docs/ai/lifecycle/03_TaskGraph.md` | `wf-queue.sh` + `ses-session-end.sh` | ❌ |
| `STATUS.md` | `wf-queue.sh` + `ses-session-end.sh` | ❌ |
| `tests/android-test-registry.yaml` | `gov-registry-sync.py` | ❌ |
| `docs/ai/lifecycle/06_Metrics.md` | `wf-queue.sh` | ❌ |
| `docs/index.md` | `gov-validate.py --fix` | ❌ |
| `AGANS.md` | PR + 评审 | ❌ |

功能分支**只允许提交**: 自己的代码 + 自己的测试 + 自己的文档。

## 如何执行

### pre-commit 阶段
`gov-pre-commit` 会扫描暂存区，如果发现功能分支改动命中共享文件清单 → 直接拒绝提交。

### 合并队列阶段
队列是**唯一允许写共享状态**的自动化：
1. `wf-queue.sh run` — 合并候选 → 一次验证 → 推送 master
2. `ses-session-end.sh` — 会话结束自动审计 + 清理
3. `gov-board-reconcile.sh` — 以合并事实回填任务板，追加 `notes` → `DEC-073`

### 逃生口
`ALLOW_SHARED_FILE_WRITE=1` 环境变量 + `--force` 可绕过，但会打印审计日志。

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 钩子拒绝 + 队列唯一写（采纳） | 5/5 | 把"不要改共享文件"变成"不能改"，AI 不需要临场判断 |
| 告诉 AI 不要改共享文件 | 2/5 | 实测每天都会忘记一次 |
| 合并时自动 strip 共享文件改动 | 3/5 | 语义冲突在 strip 前已产生，定位困难 |
