# DEC-083: 一个变量两种语义 —— 治理暂停与工作模式必须分开

## 现象

`GOV_MODE` 同时承载两件事：

| 用途 | 取值 | 来源 | 文档 |
|---|---|---|---|
| 工作模式 | `explore`/`docs`/`test`/`code`/`gov` | `.ai/current-mode.json`（HMAC + TTL） | `docs/ops/GC-mode-system.md` |
| 治理暂停 | `off` | `.ai/gov-mode.json` 或环境变量 | `AGENTS.md` §0.1 |

两套文档互相不提对方。新 AI 读完 AGENTS.md 根本不知道有 5 档模式；
写完模式代码的人也不会去看 `gov-mode.sh` 的 `off` 分支。

## 根因

1. **命名冲突**：`GOV_MODE=off` 与 `GOV_MODE=explore` 共享变量名，判定分支靠代码顺序侥幸不撞。
2. **校验可绕过**：三个钩子都写成 `if [ -z "${GOV_MODE:-}" ]` 才去读模式文件。
   于是 `GOV_MODE=explore git commit` 直接跳过 4 模块编译，**而且不产生 `.ai/audit/bypass.jsonl` 记录**——
   HMAC 签名与 TTL 形同虚设。这是安全洞，不只是命名问题。
3. **入口分裂**：暂停要记 `gov-mode.sh off`，模式要记 `wf-mode.sh switch`，两个脚本、两套词。

## 决定

1. `GOV_MODE` 只表示工作模式。治理暂停改用 `GOV_SUSPEND=1`（一次性）或 `gov-mode.sh off`（计时）。
   `GOV_MODE=off` 保留兼容但打废弃告警。
2. 新增 `gov_mode_sanitize_env()`（`gov-mode-lib.sh`）：只放行 `dev`/`code`/`gov`；
   `explore`/`docs`/`test` 一律 unset 并告警——宽松模式必须由 `wf-mode.sh switch` 写入签名文件。
   在 pre-commit / pre-push / local-ci 三个入口调用。
3. `wf-mode.sh` 新增 `suspend` / `resume`，收编 `gov-mode.sh off/on`，对外只留一个 CLI。
4. `AGENTS.md` 增加 §0.2「工作模式（5 档）」指向 `GC-mode-system.md`，§0.1 改名「治理暂停」；
   同时修掉 §1/§4/§6 里指向已删除的 `scripts/governance/entrypoints/gov-validate` 与
   已退役的 `orchestrator/registry.py` 标签体系（§3 改为真实脚本清单）。

## 未完成（明确不做）

- `.ai/current-mode.json` 的 HMAC 密钥仍由仓库路径推导，不是真密钥；防的是手误与跨仓复制，不防蓄意伪造。
- 未做「同一 worktree 多会话各持一份模式」——`current-mode.json` 仍是单文件。

## 验证

| 检查 | 命令 | 期望 |
|---|---|---|
| `GOV_SUSPEND=1` 单命令暂停 | `. gov-mode.sh && gov_mode_is_off` | 返回 0 |
| 未签名宽松模式被清洗 | `GOV_MODE=explore . gov-mode-lib.sh; gov_mode_sanitize_env` | `GOV_MODE` 变空 + 告警 |
| 严格模式不被误删 | `GOV_MODE=dev` / `code` / `gov` | 原样保留 |
| 旧写法兼容 | `GOV_MODE=off` | 告警 + 判定为暂停 |
| 收编入口可用 | `wf-mode.sh suspend 30s` → `gov-mode.sh status` | `off` → `on` |
| 无模式文件不误报 | 删除 `.ai/current-mode.json` 后 `gov_mode_warn` | 无输出（原为 "HMAC 校验失败"） |
| 真篡改仍报警 | 改 `mode` 字段保留旧 hmac | `HMAC mismatch` 告警 |
| 批次环不回归 | `bash scripts/governance/gov-local-ci.sh` | PASS |
