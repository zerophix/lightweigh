# DEC-010: 模板版本化 + gov-upgrade.sh 升级路径 — 关闭分叉腐化缺口

> 版本事实源 gov-template-version；拥有区清单（gov-owned.list）定义升级边界——只动上游拥有的文件，项目自有配置与分叉扩展永不触碰。

---

## 决策

NOTE-20261014-002 分叉体检的 P0 结论：模板没有版本号与升级机制，分叉宿命是
三方发散（上游修的它不知道、上游加的它没享受、它自长的上游看不见），只能
人工逐文件收敛——web-ai-bridge 因此腐化 41 天累积 131+ 违规。本决策关闭该缺口：

1. **版本事实源**：`scripts/governance/gov-template-version`（当前 1.1.0 = 模板
   带 DEC-004~009 全部修复的版本）；gov-generate-status.py 版本优先级改为
   根 VERSION → gov-template-version → package.json，STATUS 仪表盘自动显示。
   版本号语义：PATCH = 修校验器缺陷；MINOR = 新增规则族/工具（升级面变化）；
   模板任何拥有区行为变更随提交评估是否 bump。
2. **升级工具 gov-upgrade.sh**：
   - `--check <源>`：对比本地与源的版本号 + 拥有区逐文件差异，只报告不修改
   - `--apply <源>`：差异文件先备份到 `.cache/upgrade-backup/<时间戳>/` 再同步
   - `<源>` 为另一份模板 checkout（本地路径）；未来可扩 git remote
3. **拥有区边界 = gov-owned.list**：上游拥有的脚本、modules/、hooks、
   registry、版本文件。**刻意排除** `gov-config.sh`（项目源码目录配置）与
   `gov-custom-checks.sh`（项目自定义检查）——它们虽住 scripts/governance/，
   但内容属项目所有；分叉自有的扩展（policy 引擎系、baseline 校验）不在
   清单内，升级永不触碰。
4. **测试**：清单条目全部存在于仓库、版本号格式合法、tmp 分叉上
   --check 报差异且不改文件、--apply 备份旧文件并同步到与源一致。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 拥有区清单覆盖了分叉腐化最痛的文件（校验器+modules+钩子） | 清单维护纪律 | 升级后部分缺陷仍在 | 已验证（清单含全部 gov-*/modules/钩子源） |

| A3 | gov-config.sh/自定义检查排除在外是正确边界 | 项目自有内容不进上游清单 | 项目配置被覆盖 | 已验证（清单注释显式声明） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|------|
| 版本文件 + 拥有区清单 + check/apply（采纳） | 5/5 | 边界显式、备份可回滚、体检先行，分叉零风险试用 |
| 全目录同步 scripts/ | 1/5 | 覆盖 gov-config 与分叉扩展，制造数据损失 |
| 只做版本号不做升级工具 | 2/5 | 分叉知道落后多少，仍要人工收敛——缺口关闭一半 |
| 升级工具直接接 git remote pull | 3/5 | 需要分叉有远程且网络可达；本地路径模式先行更稳（A2） |

## 已知局限

- 清单是显式列表：新增拥有区文件需同步编辑清单（有清单完整性测试兜底）。
- `--apply` 对清单内被分叉深度改造的文件会覆盖（有备份可回滚），使用纪律
  是先 `--check`、看差异、再决定；深度分叉文件应从清单剔除或改为项目自有。
- git remote 模式（`--source upstream`）未实现，当前要求本地路径（先 clone）。
