# DEC-079: 机械变更无需认领 —— 只改 import/format 的改变，免于流程

> 2026-10-24 复盘：开发者花 30 秒清理一个 unused import，
>却被要求认领任务 / 建 worktree / 写证据 —— 浪费 5 分钟。
> 根因：流程对"有副作用的改动"和"无副作用的机械改动"没有区别。

---

## 什么是"机械变更"

| 类型 | 示例 | 是否需要认领 |
|---|---|---|
| import 清理 | 删除 unused import | ❌ |
| 格式化 | `ktlint --format` 改代码 | ❌ |
| 依赖升级 | `--update` 升级版本号 | ❌ |
| 变量重命名 | `refactor` 全局改名 | ✅ |
| 功能添加 | 新文件 / 新接口 | ✅ |
| 治理脚本改动 | 修改 `gov-*.sh` | ✅ |

## 检测

`wf-claim.sh` 在 `--profile-force` 或 `--machine` 模式下，
通过 `git diff --name-only` 检查改动文件：

```bash
if only_imports_and_format(files); then
    echo "机械变更：跳过认领"
    exit 0
fi
```

## 逃生口

`FORCE_TASK_CLAIM=1` 可强制要求认领，供评审需要时使用。
