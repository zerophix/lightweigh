# DEC-032: CI 环境跳过阿里云镜像（Gradle 遇 5xx 不回退后续仓库）

> runner 访问阿里云三个镜像全部 502，而 Gradle 在插件解析遇到 5xx 时会直接终止、不回退后面的仓库；
> 排在首位的镜像因此把整个解析带崩，真正的官方源根本没被问到。

---

## 决策

DEC-031 把 KSP 从 `2.3.2` 钉到 `2.3.9` 后，CI 报的是**同一个错**：`Plugin [id: 'com.google.devtools.ksp', version: '2.3.9'] was not found`，
照旧列出六个源。版本假设被否证——故障不在版本，在 runner 侧对仓库的解析。

取证（临时在 ci.yml 加探针，从 runner 视角逐源请求 KSP marker 并打印状态码，取证后已删除）：

| 源 | runner 看到的返回 |
|----|------------------|
| `https://maven.aliyun.com/repository/google` | **502** |
| `https://maven.aliyun.com/repository/gradle-plugin` | **502** |
| `https://maven.aliyun.com/repository/public` | **502** |
| `https://dl.google.com/dl/android/maven2` | 404（KSP 不在 Google Maven，属正常） |
| `https://repo.maven.apache.org/maven2` | **200**（artifact 确实存在、可达） |
| `https://plugins.gradle.org/m2` | 303（正常重定向） |

`./gradlew build --info` 的日志给出了失败机制：

```
Downloading https://maven.aliyun.com/repository/google/.../org.jetbrains.kotlin.android.gradle.plugin-2.2.10.pom
Resource missing. [HTTP HEAD: ...]                      <- 其它插件：镜像回 404，Gradle 继续往后找，成
Failed to get resource: GET. [HTTP 502: .../com.google.devtools.ksp.gradle.plugin-2.3.9.pom]
Failed to get resource: GET. [HTTP 502: ...]            <- 重试
Failed to get resource: GET. [HTTP 502: ...]            <- 第三次重试后终止
```

**结论：Gradle 的解析在遇到 5xx 时终止整个查找，不像 404 那样回退到下一个仓库。**
阿里云镜像排在 `pluginManagement.repositories` 第一位且恰好对这条路径返 502，于是解析在第一个仓库就死了，
`google()` / `mavenCentral()` / `gradlePluginPortal()` 一个都没被问到——这才是「六源全未命中」的真相，
也解释了为什么换版本毫无效果。

采纳的修法是**按环境分流仓库**，而不是改顺序或删镜像：

- **采纳：CI 环境跳过阿里云镜像**。`settings.gradle.kts` 的两个 `repositories` 块加 `if (System.getenv("CI") != "true")`，
  CI（GitHub 设 `CI=true`）只用官方源，本地（未设该变量）保持「阿里云优先、官方兜底」的原策略。
- **否决：官方源排到镜像前面**。文件原注释已写明「`google()` 直连超时会拖垮整个构建」，这是国内网络的既有取舍；
  为救 CI 而牺牲本地体验属于拆东墙补西墙。
- **否决：删掉阿里云镜像**。同上，且会让国内全新环境（无缓存）无法构建。
- **否决：保留现状，靠本地缓存与人工判断**。CI 恒红，门禁失效。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | GitHub Actions 会设置 `CI=true` | Actions 的标准环境变量约定 | 分流不生效，CI 继续走镜像 | 已验证（分流后连续三轮 master 推送全绿；等价的插件解析失败未复现，且成功轮次日志中无 HTTP 502） |
| A2 | runner 能正常访问官方三源 | 官方源对 GitHub 云环境可达 | CI 仍无法解析依赖 | 已验证（探针：Maven Central 200、Plugin Portal 303；Google Maven 对 KSP 返 404 属正常，构建期对被托管的 androidx 依赖可达） |
| A3 | 阿里云的 502 是持续性的而非瞬时抖动 | 该 502 与地理位置/出口网络相关 | 分流变成不必要的复杂度 | 已观察（三次独立运行均失败，且探针三条路径同时 502；非单次抖动） |
