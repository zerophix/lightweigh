# DEC-084: 审阅一致性与证据溯可

> 在 lightweigh 治理框架落地时，确保审阅（local-ci / pre-commit / merge）的状态与真实代码一致。

---

## 决策

采用最小摩擦、可验证的三项变更，解决审阅过程中发现的「状态漂移」问题：

1. **证据绑定规则版本**：`gov-local-ci.sh` 在写入 `local-ci-last.json` 时，附加 `rule_version`（`scripts/governance|hooks|workflow` 的 SHA）与 `check_set_hash`（步骤清单的 SHA）。这样一次审阅过的记录，经规则变更后自动失效，防止「规则改了但旧结论沥洞」。
2. **docs/review 快路径**：`gov-pre-commit-simplified` 对纯文档变更（`docs/`, `design/`, `*.md`, `.ai/`, `.cache/`, `.opencode/`）或 `review`/`docs` 角色，跳过会话归属与任务锁校验；角色/画像作用域校验与分支/密钥检查不变。评审人员与写文档的人不再被 block。
3. **合并后回填检查**：`gov-merge.sh` 在 `gh pr merge` 后执行 `gov-board-reconcile.sh --dry`，如检测到任务仍需回填则明确提示动作。不直接回写 trunk（保留单一写者原则），仅做可见性兜底。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |

| A3 | `wf-queue` 是回填的唯一写者 | queue 路径合并到 trunk | gov-merge 仅提示 | 接受为中间态 |
