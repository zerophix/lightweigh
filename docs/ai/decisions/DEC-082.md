# DEC-082: 门禁静默失效 —— hooksPath 必须锚定主树

> 2026-10-27 实测：`core.hooksPath` 指向 `lightweigh-backfill-dec-072-080/scripts/hooks`，
> 该 worktree 已于当日 02:00 前后被收尾流程删除。git 对不存在的 hooksPath **不报错**，
> 直接跳过 pre-commit / pre-push / commit-msg —— 三层门禁同时归零，无人察觉。
> 当日上午 master 上出现两条单亲直提交（`4014058`、`5e3d992`），`hook-trail` 无记录。

## 根因

| 环节 | 事实 |
|---|---|
| 写入 | `gov-hook-doctor.sh --fix` 用 `$ROOT/scripts/hooks` 推导 EXPECTED，`$ROOT` 取自脚本位置 |
| 触发 | 在某 worktree 内执行 `--fix`，EXPECTED 变成该 worktree 的绝对路径 |
| 共享 | worktree 共用同一份 `.git/config`，一处写入，全仓生效 |
| 引爆 | 该 worktree 被 `gov-merge.sh` / `ses-session-end.sh` 自动删除 → 悬空 |
| 掩盖 | 诊断器只在 local-ci（慢层）跑；钩子坏了 → 提交不受限 → 更没人跑 local-ci |

这与 DEC-073 注释里「所有 worktree 共用一份」的设计意图正好相反，属于实现与意图背离。

## 决定

1. EXPECTED 改用 `git rev-parse --path-format=absolute --git-common-dir` 反推主树，不依赖脚本位置。
2. `ses-session-begin.sh` 在会话入口自动 `--fix`（幂等，只改一行配置）。理由：这是唯一必然被执行的时机；门禁坏了时人不会主动去跑慢层诊断。
3. 编码检查的 `[^\x00-\x7F]` 改为 `[^ -~]`。BSD grep（macOS 默认）不支持 `\xHH`，旧写法被解释成普通字符集从而匹配一切，对任何含 `$VAR` 的行误报——门禁恢复后立刻暴露。
4. 并发守卫改按 `session_id` 去重。旧口径按 ctx id 去重，导致同一会话跑 N 次 session-begin 被算成 N 个并发会话（实测 9 条同属一个会话），正常提交被自己的守卫拦住。

## 未完成（明确不做）

- 历史 `context.jsonl` 中无 `session_id` 的旧记录无法回溯，2h 窗口内仍按 id 计数；过期后自愈。
- 自愈只覆盖配置与执行位，不覆盖「源脚本被删」。后者由 doctor 的源脚本存在性检查覆盖。
