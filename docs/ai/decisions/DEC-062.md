# DEC-062: T-084/T-096 沿用呈现式交付，隐私授权只经回调

> 周总结与成员权限、隐私五态都只新建页面；空数据不估算，授权不在 UI 里落库。

---

## 决策

### 背景

DEC-061 已规定 Wave 1 新屏以呈现式组件交付，避免新建四件套去抢 Wave 2 的既有 Screen/ViewModel。
T-084 的禁区写明不得改 `AiScreen` / `AiViewModel`（那是 T-083）。
T-096 的禁区写明不实现真实授权写入，并要求单文件超过 400 行就按 view 拆开。

### 决策内容

1. **T-084 只新增两个呈现式文件**。周读数与成员权限由参数传入；保存、断开设备、生成下周计划都是回调。
   体重、体脂或日期缺失，以及非有限数值，渲染 [QkEmptyState]，不填样例数字。
2. **不除零**。测量天数为 0 时日均变化返回空，计划天数为 0 时天数标签不做除法；
   目标与起点相同（跨度为 0）时进度为空，不画假进度条。
3. **T-096 的授权状态机是纯函数** `reducePrivacy`。只有同意、仅本机、确认撤回把 `persist` 置真，
   由 `onPersistConsent` 交给既有流程。预览降级、保持开启、重新开启都不写存储。
   重新开启只回到授权页，不自动变成已授权。
4. **隐私 UI 按 view 拆成三个文件**，每个都低于 400 行：`PrivacyAuthFlow.kt` 放状态、文案与分发，
   `PrivacyConsentPages.kt` 放授权与已授权，`PrivacyRestrictedPages.kt` 放未授权、咨询与删除规则。
   文案常量留在目标文件 `PrivacyAuthFlow.kt`，保证原型短语能被闭环脚本看到。

### 明确不动的

- 不改 `AiScreen.kt`、`AiViewModel.kt`、`AiUiState.kt`
- 不新建隐私或 AI 的 ViewModel / Route（接线留给后续波次）
- 不改 Room schema、黄金向量、QkTheme

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 调用方能提供周起止体重与体脂 | 接线任务补字段 | 页面长期停在空态 | 未验证（接线不在本波） |
| A2 | 授权持久化已有流程可接回调 | 后续把回调接到现有隐私存储 | 用户同意只留在内存 | 未验证（本任务禁止写入） |
| A3 | 原型中文短语写进目标文件即可通过文案门禁 | gov-prototype-verify 按文件包含关系统计 | 匹配率告警 | 已验证（目标文件匹配率为 100% 或单文件高于 30%） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 呈现式组件 + 纯函数状态机（采纳） | 5/5 | 不越 target_files，空态与除零可单测，授权不落库 |
| 为隐私新建四件套并写入 Preference | 1/5 | 违反 T-096 禁区，也扩大与后续接线的冲突面 |
| 五态塞进一个文件 | 2/5 | 超过 400 行，任务明确要求拆分 |
