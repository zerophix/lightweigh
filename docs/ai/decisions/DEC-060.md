# DEC-060: 僵尸任务规则改为按停滞时长判定，不再拦截认领中的任务

> GOV-PROTO-003 消息声明「超过 24 小时」，实现却不比时间，导致任务一经认领即无法通过校验；pre-commit 与 pre-push 都跑 gov-validate，等于禁止在工作过程中提交。

---

## 决策

### 问题（实际发生）

```python
# 改前
zombie = [t for t in tasks if t.get("status") == "in_progress"]
if zombie: fail("GOV-PROTO-003: 存在僵尸任务（in_progress 超过 24 小时）: ...")
```

- **声明与行为不符**：消息写「超过 24 小时」，实现是「只要 in_progress 就 fail」，没有任何时间比较
- **后果**：`gov-pre-commit` 第 254 行与 `gov-pre-push` 第 2/3 步都执行 gov-validate，
  因此任务从 `take` 到 `done` 之间**任何提交与推送都会被拦**。多提交的正常开发流程直接不可行。
- **为何长期未暴露**：该规则**零测试**（`test_governance_negative.py` 无 GOV-PROTO-003 断言），
  且此前无任务恰好在 in_progress 状态下运行校验 —— 又一个 Q3「无测试即 hope-ware」的实例。

2026-10-23 开工 Wave 0（T-097/T-098 认领）时首次触发。

### 决策内容

1. **按 `updated_at`（回退 `created_at`）计算停滞时长**，`> 24h` 才判僵尸；
   与消息文案一致，也保留规则原意（认领后无人推进才叫僵尸）。
2. **保守分支**：时间戳缺失或不可解析 → 判僵尸（与「基线不可用按代码处理」同哲学：
   无法证明不是僵尸时宁可提醒，不放走真停滞）。
3. **只作用于 `in_progress`**：`pending` / `done` / `blocked` 不参与判定，避免误报。
4. **补 8 条负向测试** `tests/unit/test_zombie_rule.py`，覆盖：
   新鲜放行、30 小时必红、23.5h / 25h 边界、无时间戳保守红、不可解析保守红、
   非 in_progress 不误报、空看板放行。
   变异验证：还原旧实现 → `test_fresh_in_progress_is_not_zombie` 与
   `test_boundary_just_under_24h_passes` 立即红，还原后 8 条全绿。

### 明确不动的

- 不改 `claimed_at` 语义：`wf-task-board.sh take` 当前不写该字段，故不以它为判据
  （留作后续：若 take 开始写 `claimed_at`，应优先于 `updated_at`）
- 不放宽阈值，仍为 24 小时
- 不改 GOV-PROTO-001/002/004

## Assumptions
