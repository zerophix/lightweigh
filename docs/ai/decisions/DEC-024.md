# DEC-024: 导航状态收口 —— 从并列布尔到单一栈

> 把「当前在哪」从 7 个独立布尔的一致性，收敛为 NavState 单一事实源 + 纯函数 reduce；
> 返回语义由栈结构决定，不再由 if 的书写顺序决定。

---

## 决策

### 问题

`MainShell` 用 `tab` / `showQuick` / `showAi` / `showScale` / `reportTime` /
`featureName` / `recordType` 七个并列状态表达导航，页面优先级写死在 if 顺序里：

```
if (overlayOpen && showAi) ...
if (overlayOpen && !showAi && showScale) ...
if (overlayOpen && !showAi && !showScale && reportTime >= 0L && featureName.isEmpty()) ...
```

三层后果：新增覆盖页需回头修改全部既有条件；`rememberSaveable` 只存「哪些页面开着」，
存不下「以什么顺序开的」；全工程无 `BackHandler`，系统返回键直接结束 Activity。

### 决策内容

1. **单一事实源**：`NavState(tab: MainTab, record: NavRecord?, overlays: List<NavOverlay>)`。
   页签是根，覆盖页是栈，栈顶即当前页。所有跳转必须表达为 `NavEvent` 并经 `reduce` 返回新状态。
2. **记录表单不进栈**：保持模态替换层。理由不是视觉，而是组合语义——下层 `MeasureScreen`
   若在录入表单期间继续组合，测量会话会持有蓝牙连接。栈只装「打开即回到刚才页面」的覆盖页。
3. **返回统一**：`BackHandler(enabled = nav.canPop) { nav = nav.reduce(Back) }` 一处；
   栈空时不拦截，交还系统。二级页（历史/设置/成员）P1 起全部入栈，同一套语义。
4. **进程重建**：`listSaver` 把整个 NavState 压成字符串列表，栈序完整保存。
5. **不引入 navigation 库**：DEC-021 的 A3 假设仍未验证（详情栈刚稳定），
   先用手写 reducer 拿回正确性；将来换库时 `NavState`/`NavEvent` 作为适配边界不变。

### 有意的语义修正（非等价重构）

- 切页签现在会关闭功能页与报告页。旧实现只清 `recordType`/`showAi`/`showScale`，
  `featureName`/`reportTime` 残留，导致切页签后报告页仍压在栈上——按「导航即关闭覆盖页」
  的口径属缺陷，一并修正。
- 系统返回键关闭栈顶层，不再退出 Activity。这是本决策的主要目的。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 覆盖页层级可用线性栈表达，不存在「非栈序」的显示规则 | 页面进入关系始终是后进先出 | 出现并行互斥页时栈无法表达，需退回分支判断 | 已验证 |
| A2 | 记录表单不需要叠放，且其打开期间下层页面不应保持组合 | 测量会话的蓝牙生命周期绑定组合 | 叠放会导致录入期间蓝牙连接常驻 | 已验证 |
| A3 | 系统返回键的期望语义是「关闭当前层」，而非退出应用 | 产品口径与 Android 惯例一致 | 用户误退出，需回退 BackHandler | 待真机验证 |
| A4 | 字符串编码足以覆盖现有层类型，新增层类型必须同步 encode/decode | 层参数均为基本类型 | 新层参数丢失，恢复后落到错误页面 | 待新增层时验证 |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 单一栈 + 纯函数 reduce（采纳） | 5/5 | 优先级由结构决定；状态可 JVM 穷举测试；零新增依赖；未来可平移 navigation 库 |
| 保留布尔，仅补 BackHandler | 2/5 | 治标：返回键能用，但优先级链与进程恢复问题仍在，新增页面继续改既有条件 |
| 直接引入 navigation-compose | 3/5 | 依赖引入早于页面清单稳定，A3 假设未验证；且需先有稳定的 NavState 才能定义路由参数 |
