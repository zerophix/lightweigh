# DEC-075: 角色系统 —— 一个会话，一个角色，边界清晰

> 2026-10-24 复盘：5 个 AI 同时改同一个项目，互相踩踏 —— docs 改治理脚本、
> gov 写产品代码、review 角色认领任务并开始编码。
> 根因：没有"你能改哪里"的机器界限，只有口头约定。

---

## 五个角色

| 角色 | 可写 | 必须产出 |
|---|---|---|
| `dev` | `app/** domain/** application/** infrastructure/**` + 构建文件 | 任务证据 + 受影响测试通过 |
| `test` | 仅 `tests/**` 与各模块 `src/test/**` | 失败复现或覆盖率证据 |
| `gov` | `scripts/** tests/** docs/** .github/**` + 根规则文件 | 全量 pytest 通过 |
| `docs` | `docs/** design/** *.md` | 索引收录 + 链接可达 |
| `review` | **只读**，仅 `docs/ai/reviews/**` | 评审报告（署名会话，且 ≠ 认领者） |

## 铁律

1. **一个会话只持有一个角色**，8 小时过期。角色决定"能写哪里 + 必须交什么"，不决定门禁深度。
2. **未声明角色不得改代码或治理脚本**：pre-commit 直接拒绝。临时放宽用 `GOV_ROLE_REQUIRED=0`（会打印，评审可见）。
3. `review` 不能由持有任务锁的会话认领 —— 自审在机制上不可能。
4. `GOV_PROFILE_FORCE=1` 不能越过角色边界（只能降级画像，不能越界路径）。

## 执行

```bash
bash scripts/workflow/wf-role.sh claim gov  # 或 dev/test/docs/review
```

`wf-role.sh` 把角色写到 `.ai/roles.json`，pre-commit 读取它并校验暂存区改动是否在允许路径内。

## 状态机

```
认领 ──► worktree（单任务 / 批次两种模式）
  单任务：ses-worktree.sh add <type>/<topic>
  批次：ses-worktree.sh batch-add B-xxx
  │
  ▼
cd 到该树 → 编码/提交/推送
  （role + profile 决定门禁深度）
  ▼
PR 合入 → gov-merge.sh / wf-autopilot.sh advance 自动删 worktree + 分支
  │
  ▼
会话结束 → ses-session-end.sh 自动 workspace-doctor --fix
```
