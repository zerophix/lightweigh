# DEC-040: 全链路调试日志（同步/云/AI/认证接入 DebugLog）

> 蓝牙之外的四条链路零日志留痕（云同步成败只靠 UI notice、HTTP 异常被 runCatching 吞成 null），全部接入同一环形缓冲，悬浮球升级为全应用排障面板。

---

## 决策

1. **`BleDebugLog` 泛化为 `application.debug.DebugLog`**：改名 + 移包（`application.ble` → `application.debug`），KDoc 明确「ble/session/sync/cloud/ai/auth 全链路排障共用」及敏感信息禁入原则；MAX_LINES/语义/线程模型不变。AndroidBleLink/MeasureSession/DebugOverlay 引用同步更新，测试类更名 `DebugLogTest`。
2. **四链路插桩（约 30 处）**：
   - `SyncService`（tag `sync`）：push/restore/deleteAccount 入口与成败、guest 跳过、pushNow 中止原因（no token/subject）、四表推送条数与水位线、四表拉取失败定位（哪张表 FAILED）、合并汇总、坏行跳过（含时间戳与异常类）。
   - `CloudBaseGateway`（tag `cloud`）：`request()` 统一记 `http METHOD path -> code` 与网络异常（异常类+message）——runCatching 吞掉的超时/连接失败从此可见。
   - `CloudFunctionAi`（tag `ai`）：ask 成败（字符数/失败时 http 码与服务端 message 截 80 字）、请求层 http 码与异常。
   - `SessionStore`（tag `auth`）：验证码发送/校验/登录各分支成败、token 刷新（ok/rejected/网络失败）、session 存储（expiresIn）、signOut；`request()` 记 http。
3. **敏感信息过滤（硬约束）**：token、验证码、完整手机号禁止入日志。SessionStore 的 URL 带 `?verify_code=` 查询串，`request()` 只记 `substringBefore("?")` 的路径段；SyncService 的 cloud filter 含 userId（内部 id，非敏感）允许记录。
4. **面板标题**「BLE 调试日志」→「调试日志」。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 日志量可控（同步/AI/认证均为低频操作，单次 push 约 10 行） | 无高频轮询链路接入 | 2 万行缓冲被冲刷 | 已验证 |
| A2 | userId/内部 id 入日志无泄露风险 | 仅内部调试面板可见 | 无 | 已验证 |
| A3 | DebugLog 单向依赖（infrastructure→application）不违反分层 | 既有模式（AndroidBleLink 同款） | ArchUnit 会拦截 | 已验证（14 条规则绿） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 统一接入 DebugLog（采纳） | 5/5 | 悬浮球单点看全链路；application 纯 JVM 可用；logcat 无侵入 |
| 各模块各自 android Log | 2/5 | 排障要看两个地方；application 层不可用 android.Log；无面板聚合 |
| 引入 Timber/KLogger 库 | 1/5 | 调试用途引入第三方依赖不值；违背最小变更 |
