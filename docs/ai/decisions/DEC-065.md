# DEC-065: 治理自动化 —— 把"任何 AI 都知道该做什么"变成可执行机制

> DEC-064 定了原则（解耦/车道/单一写者/任务级并发）。本决策补上**执行层**：
> 原则若只写在文档里，就依赖 AI 自觉；本决策把四类最容易失控的动作做成脚本 + 校验 + 自动清理。

---

## 要解决的四类失控

| 失控 | 现状 | 后果 |
|------|------|------|
| 慢命令阻塞 | AI 临场判断哪些命令该后台 | 6 分钟构建卡住整个会话（一天多次） |
| 并发靠人挑 | 不知道哪些任务文件不重叠 | 重复实现 / 冲突 |
| worktree 只建不删 | 删除时机无约定、无验证 | 本地堆冗余目录与已合入分支 |
| "做完了"无机械判据 | 靠 AI 口头声称 | 合入后才发现 DoD 未满足 |

## 决策

### 1. 后台执行器 `wf-run.sh`（执行模式机械化）

```bash
wf-run.sh start <name> -- <cmd...>   # 立即返回 job id，日志与退出码落 .cache/jobs/
wf-run.sh wait <id> [--timeout N]
wf-run.sh list | tail <id> | status <id> | gc [--days N]
```

AGENTS.md §2 规定：**>10 秒命令必须走 wf-run**；裸 `&` 禁止（拿不到退出码）。该条是"约定"（无 hook 强制），但执行器使正确做法成本更低。

### 2. 工作区医生 `gov-workspace-doctor.sh`（worktree 生命周期闭环）

审计：已合入的 worktree/本地分支/远端分支、孤儿残留目录、过期认领锁、陈旧 job、证据新鲜度、master 落后。
- `--fix`：仅清理安全项（已合入分支与其 worktree、孤儿目录、过期锁、7 天前已完成 job、prune）
- `--strict`：WARN 也算失败（供收尾）
- `--json`：机器可读
- 接入 `ses-session-end.sh`：**会话结束自动审计+清理**，不再依赖 AI 记忆

### 3. DoD 校验 `gov-task-done.sh <T-xxx>`

逐条执行：`target_files` 存在 → 原型 `--strict` → `acceptance.verify_commands`。
不通过即未完成。声称 done 必须以它为准（AGENTS.md §8）。

### 4. 并行规划 `wf-parallel.sh plan`

从任务板筛选（pending + ready AC + 未被锁），按 target_files 不重叠贪心分批（默认每批 ≤3），输出建议分支名与子代理。
并发从"人挑"变成"算出来"（AGENTS.md §2）。

### 5. AGENTS.md 重写为操作手册

结构：30 秒启动 → 开工决策表 → 执行模式表 → worktree 状态机 → 解耦/车道/单一写者/合入/DoD/收尾 → **规则→执行者映射表** → 硬规则 → 命令入口 → 钩子事实。
关键：每条规则标注执行者；无执行者的显式标"约定"，不假装被强制。

### 6. 车道修正

`scripts/governance/**` 归类为 **C**（全量验证）——改门禁本身必须跑完整构建，避免"改门禁的 PR 用被改的门禁快速放行"。

## 明确不动的

- 合入权威仍是 `gov-local-ci` 全绿（DEC-048）。
- 认领、锁、DoD、审计全部**不修改任务板状态**；状态流转只由合并队列/收尾完成（单一写者，DEC-064）。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 后台执行器的 job 文件足以恢复结果 | `.cache/jobs` 不被清理过早（gc 7 天） | 结果丢失 | 已验证（测试覆盖 start/wait/exit/gc） |
| A2 | doctor 的清理范围是安全的 | 只清"已合入 + 干净"的 worktree | 误删现场 | 已验证（未合入/脏树跳过有测试） |
| A3 | 任务板字段足够规划并行批次 | target_files 准确 | 分批误判 | 已验证（重叠/不重叠/锁/limit 测试） |
| A4 | AI 会遵守"必须走 wf-run"的约定 | AGENTS.md 可读性 + 执行器低摩擦 | 仍偶发前台阻塞 | 观察项 |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 原则 + 脚本执行器 + 自动审计（采纳） | 5/5 | 把"应该"变成"一条命令"，AI 不需要临场判断 |
| 仅写进 AGENTS.md，不加脚本 | 2/5 | 依赖自觉，实测一天内就会被违反 |
| 加 hook 强制"必须后台" | 3/5 | 无法可靠识别"阻塞"（同一命令在不同上下文不同耗时），误伤风险高 |
