# DEC-028: 硬编码治理收口

> 系统性收敛项目生产代码中的硬编码：URL/域名、尺寸间距、网络魔法数字、业务文案四类，优先治理与自建后端直接相关的云绑定核心。

---

## 决策

按语言耦合度与业务风险分三组治理硬编码，均为基础设施/UI 层改动，不触碰领域规则：

- **任务 A（P0）**：网络配置集中化。同一 TCB 域名当前在 `CloudBaseGateway.kt:73` 与 `SessionStore.kt:177` 两处重复硬编码；网络参数（timeout/chunked/takeLast/trim）在 3 个网络文件内联裸数字。收敛到统一 `BackendConfig`，自建后端时只改一处。
- **任务 B（P1）**：尺寸间距 token 化。`QkSpacing` 仅 10 个文件引用，15+ Screen 直接用魔法 dp（MeasureScreen 71 处最集中）。映射到 token，缺失则扩展。
- **任务 C（P2）**：业务文案抽取。中文文案硬编码在各 Screen，未抽 `strings.xml` 资源（文件已存在，用于静态资源）。

颜色硬编码已收口到 `QkTheme.kt`（39 处全在 token 文件），不在本 DEC 范围。

### 执行结果

- **任务 A（P0，完成）**：新建 `infrastructure/config/BackendConfig.kt` 收敛 TCB 域名与网络参数。`CloudBaseGateway`/`SessionStore`/`CloudFunctionAi` 三个文件改为引用 `BackendConfig`，删除本地 `BASE` 常量与内联 timeout/chunked/takeLast/trim 裸数字。域名从 2 处重复收敛为 1 处单一来源，infrastructure 编译 + 测试通过。
- **任务 B（P1，完成）**：保守语义间距 token 化。MeasureScreen 中值恰好等于 token 的页面级间距映射（5 处 top 8dp→`QkSpacing.Sm`、2 处 start 8dp→`QkSpacing.Sm`、3 处 top 12dp→`QkSpacing.Md`）；图标 size/圆角/行内微间距保留裸 dp。app 编译通过。
- **任务 C（P2，暂缓）**：评估后暂缓全量文案抽取。326 处中文文案含大量动态值拼接（`"${value}"`、`"%.1f kg"` 等），Android 资源需 `%1$s` 占位符改造，风险高且无法测试验证（违反治理约束 Q3），当前无多语言需求。触发点=i18n 需求出现。
