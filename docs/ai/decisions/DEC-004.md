# DEC-004: R0 反思复用检测改为上下文感知 — 修复干净树必 FAIL 缺陷

> 复用检测只在提交时机有意义：工作区有未提交改动时比对 HEAD，工作区干净时比对 HEAD~1，两种上下文都不误伤。

---

## 决策

R0 的"反思内容与上一次提交完全相同"检测当前实现是：读工作区 README 反思与 `git show HEAD:README.md`
的反思比对，相同即 FAIL。这在 pre-commit 时机（工作区有未提交改动）语义正确，但在提交落地后的
任何校验场景（pre-push 钩子、CI docs-validate 干净 checkout、事后手动 validate）中，工作区 README
必然等于 HEAD，该检测 100% 误报 FAIL——本仓库首次配置远程并执行 git push 时被 pre-push 实际拦截而发现。

修复为上下文感知：

- `git status --porcelain -- README.md` 非空（有未提交改动，pre-commit 场景）：
  工作区反思不得与 HEAD 反思相同（保持原有强度：每次触碰 README 的提交必须刷新反思）。
- 为空（工作区干净，pre-push/CI/事后校验场景）：HEAD 反思不得与 HEAD~1 反思相同
  （语义平移为"最近一次提交必须刷新了反思"，与推送/CI 的审计语义一致）。
- HEAD~1 不存在（单提交仓库）或 README 未入库时跳过检测（沿用原有 try/except 容错）。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | pre-commit 钩子运行时 README 改动已处于已暂存（porcelain 非空）状态 | git add 先于 commit 钩子 | pre-commit 强度丢失 | 已验证 |
| A2 | CI docs-validate 在干净 checkout 上运行，修复后不再被 R0 永久误杀 | GitHub Actions checkout 行为 | CI 永久红 | 待验证（推送后首个 CI 运行确认） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 上下文感知：脏比 HEAD、净比 HEAD~1（采纳） | 5/5 | 两种时机都有真实约束力，无误报窗口 |
| 干净树直接跳过检测 | 3/5 | 简单，但推送/CI 失去"最近提交必须刷新反思"的审计能力 |
| 检测逻辑整体删除 | 1/5 | 退回 hope-ware：复用旧反思无人拦截 |
| 强制每次提交都改 README（现状硬编码） | 2/5 | 代码-only 提交被无谓阻塞，且在干净树上根本无法成立 |
