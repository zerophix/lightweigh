# DEC-002: 模版自一致性修复 — 文档漂移、规则速查表失真与负向测试补齐

> 模板本体的自校验声称与实际状态出现系统性偏差，一次修复消除 P0 漂移，并为校验规则补上可验证性证据。

---

## 决策

对模板本体执行 DEC-002 修复，分 4 个任务组（A/B/C/D）推进，范围限定为静态审阅发现的 P0 与 P1 问题，不引入新功能。

- 组 A（P0，文档漂移）：删除全部写死的校验项数（18 项 / 20 项 / R0-R20，共 11 处文件），
  统一收敛为单一事实源表述——规则清单与数量以 `bash scripts/governance/gov-validate.sh`
  实时输出为准；AGENTS.md 的校验规则速查表按实际引擎重写为 8 个规则族
  （R0 系列 + GOV-STRUCT / GOV-CONTENT / GOV-PROTO / GOV-SCRIPT / GOV-TEST /
  GOV-TEST-GOV / GOV-SKILL），级别列按实现标注：仅 GOV-SKILL 为 WARN，其余全部 FAIL。
- 组 A 还包含：删除 AGENTS.md 中导致后半文档落入代码块的游离围栏；
  修正 gov-generate-status.py 中的错误命令路径（validate.sh 改为 gov-validate.sh，2 处源头）；
  README 六大子系统表实际列出 7 行的计数错误。
- 组 B（P1，可验证性）：新增 tests/unit/test_governance_negative.py，用 5 个故意违规用例
  断言 GOV-STRUCT-001/002/003/004/006 确实产出 FAIL，外加 1 个空白对照用例防误报，
  落实治理设计约束 Q3：没有负向测试的规则属于 hope-ware。
- 组 C（P1，双实现收敛）：wf-next-decision.sh 与 wf-next-note.sh 改为委托 wrapper，
  实现收敛到 gov-next-decision.sh / gov-next-note.sh；同时把原子锁机制从 wf- 版本迁入
  gov-next-decision.sh，使 .clinerules / .cursorrules 中「自动编号 + 原子锁」的声称与代码一致。
- 组 D（P1，杂项）：setup.sh 步骤编号从混用的 2/4、5/6 统一为 1/5 到 5/5；
  .gitignore 的 .cache/ 改为 .cache/* 加 !.cache/.gitkeep（父目录被排除时 negation 才生效），
  使 setup.sh 创建的 .gitkeep 能被 git 追踪。
- 执行中追加发现（同属前缀重命名遗留，纳入组 A）：gov-sync-standards.sh 的 3 个功能路径
  （promote/validate/next-note）指向不存在的旧文件，set -o pipefail 下晋升流程必中断；
  gov-generate-index.sh 生成的索引模板写旧命令名；migrate/session/sync-mkdocs/update-metrics
  的用法字符串为旧路径；.claude/settings.json 的 4 个 SessionStart hook 与 9 个 skill 配置
  仍引用 scripts/docs/（R0c 规则当前必 FAIL，Claude Code 启动 hook 必报错）；
  skill 配置还残留 npx jest / tsc 命令与 24 项数字（本项目无 package.json）。

- 本 session 无 shell 工具：所有 bash / py 修改均为静态编写，未运行 `bash -n`、`py_compile`、

## 执行中追加发现（2026-10-14 提交时）

GOV-PROTO-001 实现与自身语义不符：规则名与 FAIL 文案均声称「收件箱超 48 小时未读视为违规」，
但 gov_validate_protocol.py 的实现是 `inbox_unread > 0` 即 FAIL，从未检查时间。
这与接力铁律「结束必须交接（写未读接力信）」自相矛盾：session-end 之后到下个 AI 读信之前，
任何校验与提交都会被拦截——本 session 提交时被 pre-commit 实际拦截而发现
（此前全量校验 PASS 只是碰巧收件箱无未读信）。

修复：未读信按 frontmatter timestamp（ISO UTC）→ 文件名 YYYYMMDD-HHMMSS → 文件 mtime
三级来源计算信龄，仅超 48 小时者计入违规；新增 3 个测试用例
（fresh unread 防误报回归、stale unread 必 FAIL、stale read 不违规）。
