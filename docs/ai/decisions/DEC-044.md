# DEC-044: 修复 Chipsea_BLE 混合广播版本导致的协议识别错误

> Chipsea_BLE 设备广播版本为 0x10 (OKOK 格式) 但 GATT 层使用 Chipsea 协议, 需在协议匹配时通过设备名称识别。

---

## 决策

将 Chipsea_BLE 这类 "广播 OKOK / GATT Chipsea" 混合设备的协议识别逻辑, 加入到 `Protocols.match()` 和 `ChipseaCloudProtocol.marker()` 中:

**核心变更**: 在 `ChipseaCloudProtocol.marker()` 中, 即使检测到广播版本 0x10/0x11 (OKOK), 如果扫描记录中包含设备名称为 "Chipsea" 相关的广告, 则仍然允许 Chipsea 协议匹配.

**验证方法**:
1. 从扫描记录中提取 AD 类型 0x09 (Complete Local Name)
2. 如果名称包含 "Chipsea" (不区分大小写), 跳过 OKOK 排除逻辑
3. 继续检查 Chipsea 版本 0x02

```java
// ChispeaCloudProtocol.marker() 增加名称感知 (示意):
private static int marker(byte[] data) {
    // ... 现有 F0 FF 标签查找 ...
    if (type == 0xFF) {
        if (!isChipseaDeviceName(data) && 
            (vendorVersion(data, start, end, 0x10) || vendorVersion(data, start, end, 0x11))) {
            return -1; // OKOK 设备排除, 除非名称含 "Chipsea"
        }
        int found = chipseaAt(data, start, end);
        if (found >= 0) return found;
    }
    // ...
}
```

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | Chipsea_BLE 的名称始终包含 "Chipsea" | 扫描记录 AD 0x09 | 无法识别该设备 | 已确认 (Python 扫描显示 "Chipsea_BLE") |
| A2 | 纯 OKOK 设备名称不包含 "Chipsea" | 名称规范 | 误伤 OKOK 设备 | 待验证 (检查 OKOK 设备名称) |
| A3 | Chipsea_BLE GATT 特征结构稳定 | 设备不变更 UUID | 解析错误 | 已确认 (FFF1/FFF2/2A9C/2A08) |
| A4 | 版本 0x10 的 Chipsea 设备 GATT 使用 Chipsea 协议 | 固件一致性 | 协议不匹配 | 已验证 (Python 测试: 7B 时间 + 2B 单位 + 20B 帧) |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| A. 名称感知匹配 (采纳) | 5/5 | 最简单可靠, 利用设备名称作为额外信号, 不影响纯 OKOK 设备 |
| B. GATT 探测重连 | 3/5 | 连接后发送 7B 时间包探测, 失败则回退 OKOK. 复杂, 增加连接延迟 |

| D. 仅修改 Protocols.match | 4/5 | 在协议层添加名称检查, 但是 ChipseaCloudProtocol.marker() 也会被直接调用 (单元测试) |
