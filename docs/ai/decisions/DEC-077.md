# DEC-077: 绕过审计 —— 检测到就报，评审看到

> 2026-10-24 复盘：开发者频繁用 `--no-verify` 跳过 pre-commit，
>造成"提交通过但规则未检查"的事故。当前只能在 push 时审计，
>不能阻止。

---

## 什么会被审计

`gov-audit-bypass.sh` 检测以下情况：

| 绕过动作 | 检测点 | 评分 |
|---|---|---|
| `git commit --no-verify` | commit-msg 缺钩痕迹 | 1/5 |
| `GOV_ROLE_REQUIRED=0` | 环境变量泄露到 commit | 2/5 |
| `GOV_PROFILE_FORCE=1` 越界 | env 注入 | 3/5 |
| CI=1 / CI=true 绕过 | 环境变量 | 1/5 |

## 检测机制

```bash
# 在 pre-push / local-ci / 合并队列中运行
gov-audit-bypass.sh --check
# 输出: 检测到 N 处绕过，详见 .cache/bypass-audit-<sha>.log
```

检测原理：扫描提交历史中是否有 `Signed-off-by` 之外的 commit-msg，
是否有 `no-verify` 标记，是否有环境变量泄露。

## 评审见

审计结果在 `docs/ai/reviews/` 中必显霷，评审人必须回答"为什么绕过"。
单次绕过评分 ≤ 2/5 时，PR 被拒。

## 限制

- **不能在服务端阻止** `--no-verify` push（需要 pre-receive hook，见 DEC-081）
- 只能**事后审计 + 评审挂起**
