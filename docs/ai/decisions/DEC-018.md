## Q4 决策：不变量来源分层标注 + 阻抗上界

- fat==-1 哨兵与 time>0：契约级（data-schema measurements 表）
- weight 1..400：产品级合理量程（非厂商契约——厂商协议原始过滤为 2..2000kg，
  见 proto-okok NOTE-20260908-003），代码注释如实标注区分
- impedance 补上界 5000Ω（协议合理上限）；0 为"未测出"哨兵，
  算法仅在 >0 时被调用（RecordMeasurementService 分支），零值不会被当有效读数
- 读取路径复用同一构造器：Room 脏行会在读取时 fail-fast 抛 DomainException
  （v1 无存量数据；选择显性失败而非静默清洗）

## Q5 决策：计算输入快照随记录持久化（schema v1→v2）

只存最终体脂率的历史不可解释。measurements 增三列可空 male/age_years/height_cm，
用例盖戳（读档案→算→连同输入构造聚合），MIGRATION_1_2 以 ALTER TABLE 补列。
语义三层分离：历史事实 / 计算输入快照 / 当前档案。
"存档后修改档案不改变已存记录"由用例测试固化。
输入盖戳后，原 T-001 的 profileVersion 审计戳降级为可选项。

## Q6 决策：单位换算向量落地 + 新增向量设计表

已落地 WeightValueTest 四向量（kg/斤/lb/st），各自击中：
小数位表解码、2斤=1公斤系数、英制常数精度、高低字节拆包。
设计表（T-002 执行）：哨兵分支反转→fat=-1 用例已有；舍入半值→构造 raw=x.x5 输入；
边界→age=1/127 与量程端点各一条；8 电极→isEightR 实现时启用既占位向量。
明确不以"数量"为标准，每条向量须声明所排除的故障模式。
残余不可排除项：厂商源码本身的错误——唯一闭合手段是真机数值对拍（M5）。

## Q7 决策：交付状态表 + 门禁设计（不擅启）

- README 当前状态节增"交付状态表"：每个提交链标注 可交付/阻断 及依据，
  对外表达与仓库真实状态一致（回应"验收口径"质疑）
- 多 agent 门禁设计（供人类裁决，按评审红线不单方面启用）：
  1) 每 agent 独立 git worktree + feature 分支，master 合并前必须
     在该分支 HEAD 上隔离构建+测试全绿
  2) 共享关键文件（*.gradle.kts、libs.versions.toml）列为"热文件"，
     变更提交需在提交信息声明 scope，pre-commit 校验暂存集 ⊆ 声明 scope
  3) 工具链版本文件（toml 版本段）变更强制触发全模块隔离构建
  以上登记 T-003，待人类在双方 agent 间统一启用
