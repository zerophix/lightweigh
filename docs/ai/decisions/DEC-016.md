# DEC-016: 指标文档本地化为 Android 应用指标

> 让 gov-update-metrics.sh 生成的 06_Metrics.md 反映 Android 应用本身，
> 而不是模板工具链（Shell / Python 脚本行数）。

---

## 背景

`gov-update-metrics.sh` 会整体覆盖 `06_Metrics.md`，其内置模板的「代码质量」节统计的是
治理工具链自身：Shell 脚本行数、Python 脚本行数、可执行脚本数。对以 Kotlin / Java 为主体
的 Android 工程，这些数字既无意义又会掩盖真实指标；更糟的是覆盖式写入，手写的应用指标
下次运行必然丢失。

模板虽提供 `metrics-hooks/` 扩展点，但钩子的输出只能追加到「自定义指标」节，无法替换
误导性的通用节——隐患并未消除。

## 决策

- 新增项目自有钩子 `scripts/governance/metrics-hooks/00-document.sh`（该目录不在
  gov-owned.list，模板升级不覆盖）：输出整篇 06_Metrics.md 正文，分「代码规模 / 领域资产 /
  质量门禁 / 文档健康 / 迭代进度」五节，数值全部实时计算，不写死：Gradle 模块数、
  Kotlin + Java 文件与行数、测试规模、协议实现数、体成分算法数、黄金向量条数、
  DEC / NOTE / GC / REF 计数、校验违规数、当前迭代。
- `gov-update-metrics.sh` 增加通用覆盖入口：若 `metrics-hooks/00-document.sh` 存在、
  可执行且 stdout 非空，则其输出直接作为整篇文档；否则回退到内置模板（其他项目行为不变）。
- 钩子支持 `METRICS_SKIP_VALIDATE=1` 跳过 gov-validate 调用，避免
  pytest → 钩子 → gov-validate → pytest 的递归。
- 新增 `tests/unit/test_metrics_localization.py`：钉住钩子的 Android 指标输出、
  覆盖入口存在、以及落盘文档无模板残留（漂移守卫）。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | metrics-hooks/ 不受脚本前缀校验约束 | GOV-SCRIPT-002 只校验目录内的文件 | 钩子触发校验 FAIL | 已验证 |
| A2 | 覆盖入口对未配置项目无副作用 | 无 00-document.sh 时走原路径 | 其他项目指标文档改变 | 已验证 |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 项目钩子 + 脚本覆盖入口（采纳） | 5/5 | 脚本保持通用，Android 指标落在项目自有区；上游可继续演进 |
| 直接改写脚本内置模板为 Android | 3/5 | 硬分叉上游文件，升级冲突且不可复用 |
| 仅追加「自定义指标」节 | 2/5 | 误导性的通用节仍在，隐患未除 |
