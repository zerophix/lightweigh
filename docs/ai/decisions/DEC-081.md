# DEC-081: 服务端强制 —— pre-receive hook 作为无法绕过的最后防线

> 2026-10-24 复盘：开发者用 `git commit --no-verify` 跳过 pre-commit，\n> 推送后才能被 `gov-audit-bypass.sh` 发现 —— 已经晚了。\n> 根因：本地钩子只能"可被绕过"，服务端才能"不可绕过"。\n

---

## 决策

### 单一真源: `.ai/roles.json`（DEC-074 / DEC-075 派生）

路径白名单不再硬编码在钩子脚本里，而是从 `.ai/roles.json` 派生（DEC-064）:

| 来源 | 字段 | 用途 |
|---|---|---|
| `.ai/roles.json` | `roles.*.allow` | 该角色允许修改的路径前缀 |
| `.ai/roles.json` | `roles.*.deny` | 该角色禁止修改的路径前缀 |
| `.ai/roles.json` | `roles.*.profile` | 与 DEC-074 画像绑定 |
| `scripts/governance/gov-profile.sh` | `allowed()` 函数 | 校验单路径是否被画像允许 |
| `.github/hooks/pre-receive` | `SHARED_FILES` 数组 | 服务端共享文件清单 |

### 服务端防线: pre-receive hook

`.github/hooks/pre-receive` 在收到 push 时执行，检查每一组 ref:

| 检查 | 原理 | 越界后果 |
|---|---|---|
| `--no-verify` 检测 | `git rev-parse ${sha}^{tree}` 不在 `.cache/hook-trail.log` | ❌ 拒绝 push |
| 共享文件越写 | `git diff-tree --name-only` 检测到 `SHARED_FILES` 命中 | ❌ 拒绝 push |
| 提交格式 | 正则 `^(feat|fix|docs|...)\(...\): .{1,72}$` | ❌ 拒绝 push |
| 分支命名 | `^(feat|fix|docs|...)/<topic>$` | ❌ 拒绝 push |

### 豁免名单 (允许写共享文件)

| ref | 原因 |
|---|---|
| `refs/heads/master` | 合并队列 + 收尾自动化是唯一写者（DEC-064/073） |
| `refs/heads/chore/integration-*` | 临ʱ集成分支 |
| `refs/heads/chore/board-*` | 任务板回写 |
| `refs/heads/chore/lifecycle-*` | 生命周期更新 |
| `refs/heads/chore/evidence-*` | 证据提交 |

合并提交 (`parents > 2`) 和 `chore(merge):` / `Merge ` 提交自动跳过。

### 部署

#### GitHub Enterprise / 自建 Git 服务器

```bash
# 在服务器上安装
cd /path/to/repo.git
git config core.hooksPath /path/to/checks
ln -sf $REPO/.github/hooks/pre-receive $REPO.git/hooks/pre-receive
```

#### GitHub.com（无 server-side hooks）

GitHub.com 不支持 pre-receive hooks。替代方案:

1. **Required checks**: `ci.yml` 运行 `gov-audit-bypass.sh --block` + `gov-validate.sh`
2. **Branch protection**: master 保护 + PR 必须通过审查
3. **PR 模板**: 勾选 "确认所有提交经过 pre-commit" 复选框

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| pre-receive hook + CI required checks（采纳） | 5/5 | 本地+服务端双层防线 |
| 仅靠本地 pre-commit | 2/5 | `--no-verify` 可直接绕过 |
| 仅靠 CI (push 后审计) | 3/5 | 检测滞后，无法阻止已写入 |
