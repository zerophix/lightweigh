# DEC-015: 修复构建链中断——发行版获取超时、JVM 版本不足与 Room/KSP2 不兼容

> 用户报告 gradle-9.4.1-all.zip 下载超时；逐层排查后发现三个叠加故障，
> 修复后 `./gradlew build` 全绿（含测试、lint、debug/release 打包）。

---

## 背景

用户报告 Gradle wrapper 报错：无法从腾讯镜像安装 `gradle-9.4.1-all.zip`，
原因 `java.net.SocketTimeoutException: Read timed out`。排查中发现这是三个叠加问题，
前两个被第三个掩盖。

**故障一：发行版下载无法完成。**
`gradle-wrapper.properties` 指向腾讯镜像的 `-all` 包（238 MB）。该镜像对
`-all.zip` 返回 `x-cache-status: BYPASS`，叶节点未缓存，实测速率约 1~3.5 MB/s 且会
中途停滞。关键点：Gradle wrapper 的下载器不支持断点续传，每次失败都从第 0 字节重来，
因此 `.part` 文件长期停在 128 MB / 238 MB，反复超时。

**故障二：JVM 版本不满足 Gradle 9 要求。**
开发机唯一 JDK 为 Corretto 8（`JAVA_HOME` 为空，`java` 默认指向 8）。
Gradle 9.4.1 运行要求 JVM 17+，实际报错为
`Gradle requires JVM 17 or later to run. Your build is currently configured to use JVM 8.`
本机另有 Android Studio 自带 JBR 21 与 Homebrew OpenJDK 26 可用。

**故障三：Room 2.6.1 与 KSP2 不兼容。**
发行版装上、Gradle JVM 换成 21 之后，构建推进到
`:infrastructure:kspDebugKotlin` 才失败，报 `unexpected jvm signature V`。
依赖树证据：`room-compiler:2.6.1` → `room-compiler-processing:2.6.1` →
`symbol-processing-api:1.9.0-1.0.13`，即 Room 2.6.1 编译期绑定的是 KSP1 API；
而本项目使用 KSP2（`ksp = 2.3.2`）搭配 Kotlin 2.2.10。触发点是
`MeasurementDao.upsert(po: MeasurementPo)` 为 `suspend` 且返回 `Unit`，
Room 的 `InsertionMethodProcessor` 在 KSP2 下解析其 JVM 签名时抛异常
（google/ksp#2957 记载的已知缺陷，社区收敛的解法是升级 Room 至 2.8.x）。

**为何此前从未暴露：** 构建从未越过第二个故障的 JVM 检查，因此第三个问题
在本机一直没有机会被执行到——这是"源码未变更但依赖组合已失效"的典型潜伏故障。

## 决策

- **发行版获取**：将 `gradle-9.4.1-all` 完整落盘到项目内
  `gradle/dists/gradle-9.4.1-all/`（该目录已在 `.gitignore`），使 wrapper 免网络启动；
  清理遗留的 109 MB `.part` 残片。提交后的 `distributionUrl` 维持不变，本次不改动。
- **Gradle JVM**：开发机以 Android Studio 自带 JBR 21 作为 Gradle JVM，写入
  `~/.zshrc` 的 `JAVA_HOME`（机器局部配置，不入库，不影响 CI 与 macOS 之外的机器）。
  README 已声明"JDK 17+（推荐 Android Studio 自带 JBR 21）"，此改动把该前提落到实处。
- **Room 版本**：`gradle/libs.versions.toml` 中 `room` 由 `2.6.1` 升级为 `2.8.5`。
  Room 2.7.0 起正式支持 KSP2，2.8.x 为该缺陷的收敛解。
- **不扩大改动面**：`compileSdk` 维持 34（SDK 34 与本机 `build-tools 34.0.0` 已在位），
  Room schema 快照 `infrastructure/schemas/.../1.json` 经构建校验未被改写，
  即数据库版本与表结构未变，无需 Migration。

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 升级 Room 至 2.8.5（采纳） | 5/5 | 消除 KSP2 不兼容根因；测试、lint、打包全部通过 |
| 给 DAO 的 `@Insert` 显式补返回类型绕过 | 3/5 | 改动最小，但保留 Room 2.6.1 与 KSP2 这一不受支持的组合，同类缺陷会再次出现 |
| `ksp.useKSP2=false` 回退 KSP1 引擎 | 2/5 | KSP 2.3.2 已无 KSP1 引擎，且与 Kotlin 2.2 配套的 KSP1 线路属弃用方向 |
| 改用 `-bin` 发行版（137 MB）替代 `-all` | 3/5 | 可降低下载体积与超时概率，但未触及本次真正的构建阻塞点，故仅记为后续可选项 |

## 验证

开发机以 JBR 21 作为 Gradle JVM 后，`./gradlew build` 结果：

`:infrastructure:testDebugUnitTest` 四个模块的单元测试，各模块 lint，
以及 `app` 的 debug 与 release APK 打包。`git diff infrastructure/schemas` 为空，
证实 A2。
