# DEC-030: 构建层启用 core library desugaring（取代 @RequiresApi 与 minSdk 提升）

> java.time 需要 API 26 而工程 minSdk 为 24，选定在构建层脱糖解决，而不是抬 minSdk 或给调用链打注解。

---

## 决策

`HistoryScreen` 现用 `java.time`（`Instant`、`ZoneOffset` 等），而 `java.time` 自 API 26 起才进平台，工程 `minSdk = 24` 且从未启用脱糖，于是 lint 的 NewApi 检查必然报错。三条路径里选构建层脱糖：

- **采纳：启用 core library desugaring**。在 `:app` 与 `:infrastructure` 两个模块打开 `isCoreLibraryDesugaringEnabled`，并挂 `coreLibraryDesugaring` 依赖（`desugar_jdk_libs 2.1.5`，登记在 `gradle/libs.versions.toml`）。脱糖把 `java.time` 这类 Java 8 以上 API 的实现在构建期补进 APK，运行时在低版本平台照常可用，业务代码与调用方都不需要任何注解或分支。
- **否决：把 `minSdk` 抬到 26**。改动一行即可让报错消失，代价是直接放弃 Android 7.0 与 7.1 两类设备。这是一条覆盖面的取舍，不该为了消一条 lint 报错悄悄发生。
- **否决：在 `HistoryScreen` 及其调用链上打 `@RequiresApi(Build.VERSION_CODES.O)`**。这是把契约向上传染的写法：注解不会修复函数体，只会把「调用方必须 ≥26」这条前置条件推给每一个上游，lint 的报错点随之从函数体搬到调用点（本例即 `HistoryRoute.kt:19`），红点不消失只换位置；调用链越长，需要打注解的位置越多，最终无处可打。

### 执行结果

- **构建层（完成）**：`app/build.gradle.kts` 与 `infrastructure/build.gradle.kts` 的 `compileOptions` 增 `isCoreLibraryDesugaringEnabled = true`；两模块 `dependencies` 增 `coreLibraryDesugaring(libs.desugar.jdk.libs)`；`gradle/libs.versions.toml` 增 `desugarJdkLibs = "2.1.5"` 与 `desugar-jdk-libs` 条目。
- **源码层（完成）**：`HistoryScreen.kt` 恢复至 HEAD，不加任何注解，与基线逐字节一致（文件 diff 为零）。全量 `./gradlew build` 通过（编译 + 单测 + lint + APK 打包），`Lint found 1 error` 消失；以 `--no-build-cache --rerun-tasks` 强制重跑 lint 复核，报错确实消失而非缓存假绿。
- **归因与复发（如实记录）**：该注解在实施期间被另一会话于 16:31 重新写回 `HistoryScreen.kt`，全量构建随即再次变红，移除后恢复。同一处错误在两个会话之间反弹两次，说明真正缺的不是代码而是共识——「平台新增 API 该在哪一层解决」没有落成文字，于是两边各自以自己认为对的方式消红。本文件即为该共识的落盘：**平台新增 API 优先在构建层用脱糖解决，禁止用 `@RequiresApi` 把约束推给调用方**；判别依据是「这次改动让报错换了位置还是换了个数」。
- 曾以二分法排除干扰项：删掉 `java.time` 的用法、删掉 Material3 的 `DatePicker`、删掉 `QkDateChip` 均仍报错，把函数体换成桩则报错消失——由此确证触发点是注解本身而非依赖或资源。

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|
| 构建层启用脱糖（采纳） | 5/5 | 一处改动同时覆盖全项目的 `java.time` 及其他 Java 8+ API，业务代码零侵入，覆盖面不缩水 |
| 抬 minSdk 24 至 26 | 2/5 | 一行改动即消红，但代价是永久放弃 Android 7.0 与 7.1 设备，属产品级取舍，不应由一条 lint 报错顺带决定 |
| 在调用链上打 `@RequiresApi(26)` | 1/5 | 报错换位置而不消失；调用链越长越无处可打，且把平台约束散落到业务代码 |
| 移除 `java.time` 改写页面 | 1/5 | 为迁就构建配置去降级业务实现，本末倒置，且已在二分排查中证明改动面更大 |
