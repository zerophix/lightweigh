## Q8 决策：金丝雀断言从"声称"变为可执行 + 修复器/检测器分歧修复

- 取证结论：2ad10b3 提交信息与 README 反思曾声称"金丝雀断言已加"，
  但仓库全历史检索（-S pickaxe + 测试文件遍历）未找到任何可执行断言——
  该声称属文字级，予以撤回（零信任自证）。
- 本次在 tests/unit/test_governance_negative.py 补齐 4 条可执行金丝雀：
  1) 非键帽语境数字/#/* 原样保留（历史事故直接反例）
  2) 合法键帽被删且邻近普通字符保留
  3) 修复器处理自身定义文件零改动（自指保护）
  4) 幂等 + CRLF + ZWJ 组合 emoji + 不完整键帽混合输入
- 夹具一律用转义序列（\u20e3/\u200d/\ufe0f）构造，对一切 strip 路径免疫。
- 修复器/检测器分歧（本轮新发现的活缺陷）：GOV-TEST 检测器豁免 tests/
  （gov_validate_tests.py:76-78，注释明言"夹具必须包含被测字符"），
  但 pre-commit Stage 0a 的 strip 修复器不豁免，会在提交时吞掉测试夹具。
  决策：pre-commit 的 STAGED_TEXT_FILES 增加 `grep -v '^tests/'`，
  使修复器与检测器口径一致（属对齐既有豁免决策，非新增门禁）。
- 已验证输入空间：纯 ASCII 数字/#/*、合法键帽、自身定义源文件、
  CRLF/ZWJ/VS16 混合、重复运行幂等。
- 未覆盖输入空间：无基字符的裸 U+20E3（故意不扩正则以保自指安全，
  由金丝雀4钉为已知边界）；未列入 EMOJI_RE 码表的符号类（如 ©®™）；
  代理对/非 UTF-8 字节（open(errors) 由调用方决定，strip 本身不做转码）。
- 失败保护：金丝雀3 断言修复器永不动自身定义；检测器与修复器口径对齐后，
  夹具不再存在被钩子静默删除的路径。
