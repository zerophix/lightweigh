# DEC-005: 修复 validate 输出契约漂移 — pre-push 永远无法通过

> 摘要行恒定输出（带缩进，兼容旧消费者），pre-push 判定改用退出码，契约用测试钉住。

---

## 决策

首次真实执行 git push 时发现：pre-push 通过条件是 `grep -q "违规: 0"`，但
gov-validate.py 成功路径只打印 `全部通过`，`违规: N 项` 仅在失败路径输出——
即成功时输出中根本不存在 `违规: 0` 字样，**pre-push 在任何情况下都不会放行**。
同族问题：gov-update-metrics.sh 按 `^  违规:` 提取违规数，同样匹配不到，
STATUS 的「校验违规」指标长期恒为 `?`。两处消费者都依赖旧版
scripts/docs/validate.sh 的输出格式，Python 校验引擎重构时未同步契约；
本仓库此前无远程、指标从未被核对，缺陷一直潜伏（与 DEC-004 同一次推送暴露）。

修复：

1. **gov-validate.py**：无论成败恒定输出 `  违规: N 项`（保留两空格缩进以匹配
   gov-update-metrics.sh 既有 grep 锚点），成功时额外输出 `全部通过`。
   该改动同时修复 pre-push 的字符串判定与 metrics 的违规数提取，两处消费者
   源码无需修改。
2. **gov-pre-push**：通过判定改为命令退出码（`if OUTPUT=$(bash ...); then`），
   与 pre-commit（`GOV_VALIDATE_QUICK=1 bash "$VALIDATE_SCRIPT"`）、CI
   （`bash scripts/governance/gov-validate.sh`）的既有判定方式一致，
   解除对具体文案的耦合；失败时仍打印 FAIL 明细供人排查。
3. **契约测试**：新增用例以子进程运行 gov-validate.py（QUICK 模式防递归），
   断言输出始终含 `违规: \d+ 项` 摘要行；返回码为 0 时断言 `违规: 0`。
   任何让摘要行消失的未来改动都会被 pytest 拦下。

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|------|
| 摘要行恒定输出 + pre-push 改退出码（采纳） | 5/5 | 消费者与生产者双向收敛，且有测试钉契约 |
| 仅让 pre-push 改退出码 | 3/5 | 推送通了，但 metrics 的 `?` 指标继续潜伏 |
| 仅补摘要行 | 3/5 | metrics 修好，pre-push 仍耦合文案、脆弱 |
| 改 metrics 与 pre-push 适配 `全部通过` | 2/5 | 生产者保持坏契约，未来新消费者继续踩坑 |
