# DEC-008: 干净 checkout 适配 — R0 的 handoff 与 hooks 检查按执行环境分流

> 干净克隆模拟 CI 抓出两处必然红：记忆文件不入库（handoff 必失败）、hooks 属本机状态（clone 必缺失）；前者按「文件缺失即跳过」对齐既有先例，后者按 CI 环境变量分流。

---

## 决策

T-215 用 `git clone` 干净克隆模拟 CI 的 docs-validate job，立刻暴露 1 项违规
（`未找到 handoff 反思记录`），且追查发现它因 `fail; return` 提前返回掩盖了
**第二处必然失败**（`Git hooks 未安装`）——`.cache/context.jsonl` 被 gitignore
不入库、`.git/hooks` 不随 clone 走，两者在任何干净 checkout 上都天然缺失。
即使 GitHub Actions 账户问题解决，CI 也会永久红。

修复（延续 DEC-004 的「比对基线/检查条件随执行环境分流」原则）：

1. **handoff 检查（组 A）**：`MEMORY_FILE` 不存在时输出 INFO 跳过——
   与 GOV-CONTENT-008 的 `if not MEMORY_FILE.is_file(): [SKIP]` 既有先例对齐
   （同族检查两种行为本身就是不一致）；文件存在但无 handoff 记录时仍 FAIL
   （工作仓库的接力纪律不受影响）。
2. **hooks 检查（组 B）**：`CI` 环境变量存在时输出 INFO 跳过（GitHub Actions
   默认 `CI=true`）；本机环境继续 FAIL 强制安装。hooks 是每台机器的本地状态，
   CI 无法也不应拥有——正确语义是分流而不是删除。
3. **测试（组 C）**：缺记忆文件跳过、有记忆无 handoff 必报、CI 环境 hooks 跳过、
   非 CI 环境 hooks 必报，四向语义各一用例。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | GitHub Actions 默认设置 `CI=true` | Actions 运行器环境约定 | CI 上 hooks 检查仍红 | 已验证（官方文档行为；首次运行复核） |
| A2 | 手动 `CI=1 bash gov-validate.sh` 可在本机复现 CI 分流 | POSIX 环境变量传递 | 无法本地验证分流 | 已验证 |
| A3 | 修复后干净克隆 0 违规 | 无其他隐藏的环境依赖检查 | CI 仍红 | 已验证（克隆模拟 0 违规） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|------|
| 按执行环境分流：文件缺失跳过 + CI 跳过 hooks（采纳） | 5/5 | 两处语义都正确，本机纪律不放松 |
| 把 context.jsonl 提交入库 | 2/5 | 机器本地接力状态入库，GOV-CONTENT-009 时效检查会随仓库停摆变红，制造新问题 |
| CI 流程里安装 hooks + 强制生成记忆文件 | 1/5 | 为过校验制造假状态，比跳过更糟 |
| 两处检查整体删除 | 1/5 | 本机接力纪律与 hooks 安装提醒一起丢失 |

## 已知局限

- 本机新开 clone 未装 hooks 时 validate 仍会 FAIL——这是有意的 onboarding
  强制（README 快速开始第 2 步），不是缺陷。
- CI 环境下 handoff/记忆类检查全部空转——CI 无法验证接力纪律，该纪律只能
  在工作仓库由 pre-commit/session-end 强制（执行介质边界，接受）。
- A1 待首次真实 CI 运行复核。
