# DEC-006: README 结构规范落地 — GC 指南 + GOV-README 校验规则族

> 规范只有配上校验才不会漂移：机读层用 FAIL 规则强制，手读层用指南 + WARN 引导。

---

## 决策

alpha-studio 实测暴露：模板移植到下游后 README 结构自由生长（`### 反思` 不在
「当前状态」第一子节位、状态区后又开顶层章节、目录结构节膨胀到 75 行），而模板
对 README 的约束只有 R0（当前状态存在 + 反思非空新鲜），不覆盖章节层次。
结论与 DEC-002/004/005 一脉相承：**只写在文档里的规范必然漂移，必须变成校验**。

1. **GC 指南**（docs/guides/GC-readme-structure.md）：定义两层规范——
   - 机读层：校验器强制解析的结构契约（H1、当前状态收尾、反思首子节、章节顺序）
   - 手读层：面向读者的标准大纲（快速开始→目录结构→核心功能→相关文档→当前状态）
     及长度分级、自动生成段落标注、反例对照
2. **校验规则族 GOV-README-001~005**（gov_validate_status.py 新增
   check_readme_structure，gov-validate.py 接入主编排）：
   - 001 FAIL：首个非空行必须是 H1，且全文恰好一个 H1
   - 002 FAIL：「## 当前状态」必须存在、唯一、且为最后一个二级章节
   - 003 FAIL：「### 反思」必须是「当前状态」节内第一个三级子节
   - 004 FAIL：若存在「## 快速开始」，必须先于目录结构/架构/核心功能章节；缺失为 WARN
   - 005 WARN：缺少「## 相关文档」（深入阅读入口，建议项不阻塞）
3. **测试**：每条 FAIL 规则各一负向用例 + 一个全合规正向用例，沿用
   test_governance_negative.py 的 tmp_path + monkeypatch ROOT 模式。

## Assumptions

| ID | 假设 | 依赖条件 | 失败影响 | 验证状态 |
|----|------|----------|----------|:--------:|
| A1 | 机读层 4 条 FAIL 规则对合法 README 无误伤（模板本体 README 直接通过） | 规则只依赖标题文本与顺序 | 正常 README 被阻断 | 已验证（本仓 validate 全绿） |
| A2 | 下游项目（alpha-studio 等）按旧结构写 README 会在迁移后收到 FAIL | 下游主动升级模板 | 下游校验红 | 已知影响（规范即意图） |
| A3 | 中文/英文 README 均适用（规则只匹配 `# ` 标题语法，不匹配语言） | Markdown ATX 标题语法 | 非中文项目误伤 | 已验证（英文样例测试） |

## 方案评分

| 方案 | 评分 | 说明 |
|------|------|------|------|
| GC 指南 + FAIL/WARN 分层校验（采纳） | 5/5 | 强制项可验证、建议项不误伤，规范与实现互为证据 |
| 只写 GC 指南不加校验 | 1/5 | alpha-studio 已证明纯文档规范必然漂移（hope-ware） |
| 全部规则设为 FAIL | 2/5 | 「相关文档缺失」等建议项阻塞提交，摩擦过大 |
| 只加校验不写指南 | 2/5 | AI 只知道违反了规则，不知道正确长什么样 |

## 已知局限

- 规则基于标题文本匹配，若项目把「快速开始」改名为「Getting Started」则 004 的
  顺序检查不生效（WARN 引导仍提示缺失）——规范以中文标题为约定。
- 手读层（内容质量、行数分级）无法机器校验，靠指南约定与评审把关。
