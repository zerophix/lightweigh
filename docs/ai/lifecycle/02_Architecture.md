# 架构设计

> AI Project Collaboration Blueprint 的整体架构：一个纯文档 + 脚本的协作协议框架，不涉及运行时服务。
> 覆盖型文档：每次迭代重写，保留核心决策但不保留旧版本。

---

## 1. 系统上下文

本模板是一个**协议框架**，不是运行时系统。它由三部分组成：

```
┌──────────────────────────────────────────────────────┐
│                   项目仓库                             │
│                                                        │
│  ┌──────────────┐  ┌──────────────────┐  ┌─────────┐ │
│  │  AGENTS.md    │  │   scripts/   │  │  docs/   │ │
│  │  (协作协议)   │  │  (自动化工具链)    │  │ (文档)  │ │
│  └──────┬───────┘  └────────┬─────────┘  └────┬────┘ │
│         │                   │                  │      │
└─────────┼───────────────────┼──────────────────┼──────┘
          │                   │                  │
          ▼                   ▼                  ▼
┌──────────────────────────────────────────────────────┐
│                    AI 助手                              │
│    (人类通过 prompt 驱动 AI，AI 遵循协作协议工作)      │
└──────────────────────────────────────────────────────┘
```

## 2. 核心架构决策

| 决策 | 方案（采纳） | 替代方案 | 理由 |
|------|------------|---------|------|
| 文档架构 | 双层（黄金标准 + AI 过程） | 单层文档 | 黄金标准可追溯不丢失，AI 过程可覆盖重写 |
| 决策流转 | NOTE→DEC→lifecycle→promote→golden | 直接写黄金标准 | 渐进式成熟度，避免未定型内容进入稳定区 |
| AI 接力 | 人类枢纽闭环 (DEC-001) | AI 自主接力 | 新 AI 无记忆无义务，人类才是接力决策者 |
| 校验体系 | Python + Bash 双重校验 | 仅 Bash | Python 处理复杂规则（命名/语言/emoji），Bash 编排流程 |
| 工具链 | Shell 脚本 | 专用语言/框架 | 无外部依赖，任何平台可运行，最低心智负担 |

## 3. 模块/组件设计

### AGENTS.md（协作协议入口）

- 职责：定义 AI 在本项目中的所有行为规则
- 输入：项目上下文（git 状态、文件结构）
- 输出：AI 的行为约束和工作指引
- 关键依赖：无（纯文本规则）

### scripts/（自动化工具链）

- 职责：文档校验、生命周期管理、接力协作、指标跟踪
- 关键子模块：

| 脚本 | 职责 |
|------|------|
| validate.sh | 全量文档校验 |
| lifecycle.sh | 10 步生命周期编排 |
| session-begin.sh | AI 启动上下文加载 |
| session-end.sh | AI 收尾接力交接 |
| task-board.sh | 任务看板管理 |
| inbox.sh | AI 收件箱管理 |
| promote.sh | 晋升到黄金标准 |
| update-status.sh | STATUS.md 自动生成 |

### docs/（文档体系）

- 职责：分层存储所有项目文档
- 结构：
  - `docs/` — 黄金标准（晋升型，可追溯）
  - `docs/ai/` — AI 过程文档（覆盖型 + 追加型）

## 4. 数据流

### 决策流转路径

```
想法/讨论
  │
  ▼
NOTE-20260710-NNN（设计笔记，未定型）
  │
  ▼
DEC-XXX（决策日志，锁定方案）
  │
  ▼
lifecycle/（更新对应文档）
  │
  ▼
promote.sh → docs/ 黄金标准（晋升）
  │
  ▼
changelog/index.md（记录生效）
```

### 接力协作流

```
Session A
  │ 工作 → session-end.sh（4 项交接）
  ▼
收件箱(docs/ai/inbox/) + 任务板(.ai/tasks.json)
  │
  ▼
Session B 启动（session-begin.sh 自动提示）
  │ inbox.sh read → 问人类确认
  ▼
人类确认 → task-board.sh confirm → 开始工作
```

## 5. 约束条件

- 无外部运行时依赖（纯文档 + Shell/Python 脚本）
- 文档必须分层（黄金标准不可直接编辑）
- AI 决策必须经过 DEC 记录
- 文件名必须 ASCII 英文
- 文档语言与 `.language` 声明一致
- 迭代必须按 D→R→E→T→A→V→M→L→D→P 顺序执行
