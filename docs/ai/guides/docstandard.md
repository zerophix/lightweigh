# 文档标准

> AI 撰写文档时必须遵守的格式和质量规范。

---

## 1. 语言

- 按 `.language` 文件声明使用中文或英文
- 禁止中英文混写（代码块、技术术语除外）
- 同一篇文档全文保持同一种语言

## 2. 结构

每篇文档基本结构：

```
# 标题

> 摘要/一句话描述

---

## 1. 正文

<!-- 内容 -->

## 2. 来源（仅黄金标准需要）

## 来源: ai/decisions/DEC-XXX
```

### 标题规范

- `#` 一级标题 = 文档标题，仅一个
- `##` 二级标题 = 主要章节
- `###` 三级标题 = 子章节
- 禁止四级以上标题

### 段落

- 每段不少于 2 句
- 列表项不少于 2 条（除非单条自解释）
- 关键概念首次出现用 `**加粗**` 标注

## 3. 图表

- 技术文档必须包含至少一个 ASCII 图或 mermaid 图
- ASCII 图最小 5 行，含边框、连线、节点
- 禁止用文字描述"如下图所示"而无实际图

```
# 合格示例
┌─────┐    ┌─────┐
│  A  │ ──→│  B  │
└─────┘    └─────┘
```

## 4. 引用

- 引用外部资料用脚注 `[^1]`
- 引用项目内文档用相对路径
- 引用 DEC 用 `DEC-XXX` 格式

## 5. 禁忌

-  使用 emoji（任何文件禁止）
-  中文环境混入英文（技术术语除外）
-  TODO/FIXME 占位符留在已提交文档中
-  创建 v1/v2/bak/backup/copy 后缀的文件
-  直接编辑 docs/ 根目录的黄金标准文件

## 6. 模板示例

### DEC 模板

```
# DEC-XXX: <短语标题>

> <一句话描述决策>

---

## 决策内容

<要做什么、怎么做>

## 方案评分

| 方案 | 评分 | 理由 |
|------|------|------|
| 方案A（采纳） | 5/5 | <理由> |
| 方案B | 3/5 | <理由> |

## 状态

- 决策时间: YYYY-MM-DD
- 决策者: AI / 人类
- 来源: <触发此决策的事件>
```

### NOTE 模板

```
# NOTE-YYYYMMDD-NNN: <标题>

> <一句话描述>

---

## 背景

<问题或场景>

## 思路

<讨论内容>

## 结论（可选）

<如果已有定论>
```

## 7. 中英文术语对照表

| 中文 | English | 说明 |
|------|---------|------|
| 决策日志 | Decision Log (DEC) | 已确定的工程决策 |
| 设计笔记 | Design Note (NOTE) | 未定型的讨论记录 |
| 开发指南 | Guide (GC) | 稳定的规范文档 |
| 技术参考 | Reference (REF) | 接口/协议文档 |
| 黄金标准 | Golden Standard | 晋升后的不可编辑文档 |
| 生命周期 | Lifecycle | 每次迭代覆盖重写的文档 |
| 晋升 | Promote | 将内容从 lifecycle 写入黄金标准 |
| 校验 | Validate | 通过 gov-validate.sh（gov-validate.py 引擎）检查合规性 |

## 8. 文档审查 Checklist

提交前检查：
- [ ] 文件在 AGENTS.md 白名单内
- [ ] 命名符合规范（DEC/NOTE/GC/REF 等）
- [ ] 黄金标准标注了来源 DEC
- [ ] 内容深度 >5 行有效文字
- [ ] 无 emoji 字符
- [ ] 语言一致（按 .language）
- [ ] 无 TODO/FIXME/{{}} 等占位符
- [ ] 与其他文档不高度重复

## 9. 质量门控

所有文档在提交前会通过 validate.sh 的以下检查：

| 检查项 | 编号 | 说明 |
|--------|------|------|
| 文件结构 | GOV-STRUCT-004 | 文件必须在允许白名单内 |
| 命名规范 | GOV-STRUCT-005 | 必须符合 DEC/NOTE/GC/REF/ARCH 模式 |
| 来源标注 | GOV-STRUCT-006 | 黄金标准必须有 ## 来源 标注 |
| 内容深度 | GOV-STRUCT-007 | >5 行有效内容 |
| 语言一致性 | GOV-STRUCT-020 | 按 .language 声明 |
| 内容重复 | — | 不在 validate 内；手动运行 tools/analyze/ana-similarity.py（>88% 判重） |
