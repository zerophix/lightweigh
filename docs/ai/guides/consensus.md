# 共识指南

> 多 AI 协作时的共识达成规则。

---

## 分歧处理

多个 AI 对同一问题给出不同意见时：

**1. 证据优先** — 有执行输出 > 无执行输出

```
AI-A: "这个方案性能更好"         ← 无证据，不可采纳
AI-B: "方案A 在 1000 QPS 下     ← 有数据，优先采纳
      延迟从 200ms 降至 50ms"
```

**2. 高置信度 > 低置信度**

每条结论必须附置信度声明：

| 置信度 | 含义 | 使用场景 |
|--------|------|---------|
| 高(>90%) | 有直接执行证据 | 测试结果、lint 通过 |
| 中(70-90%) | 有间接证据 | 类似项目经验、文档引用 |
| 低(<70%) | 推理/推测 | 方案比较、风险预测 |

**3. 少数服从多数，但记录异议**

- 多数 AI 一致 → 采纳
- 分歧 → 投票，得票多者胜
- 异议必须记录在 DEC 中

## 收敛流程

```
分歧出现
  │
  ├── 各自提供执行证据
  │     ├── 有证据 → 证据驱动决策
  │     └── 无证据 → 视为推测，权重降低
  │
  ├── 仍分歧
  │     ├── 投票
  │     └── 平票 → 人类仲裁
  │
  └── 写入 DEC
        ├── 采纳方案 + 理由
        ├── 被否方案 + 否掉理由
        └── 异议记录
```

## 适用场景

- 技术方案选型
- 架构决策
- 代码评审分歧
- 优先级争议
