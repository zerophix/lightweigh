## 发现列表

### F-001 | Critical | `scripts/docs/lifecycle.sh` 缺失

**位置：** `docs/guides/GC-decision-flow.md:180`、`.claude/settings.json:7`

**描述：** `lifecycle.sh` 被文档和配置文件引用，但文件不存在。用户按文档执行 `bash scripts/docs/lifecycle.sh end "..."` 会直接报错。

**根因：** 脚本在规划中未创建，但引用先于实现被写入文档和白名单。

**修复建议：** 创建 `scripts/docs/lifecycle.sh`，实现 `end`/`begin`/`status` 三个子命令，匹配文档中的用法示例。**（已修复 ）**

---

### F-002 | Critical | `scripts/docs/session-begin.sh` 缺失

**位置：** `.claude/settings.json:28-59`

**描述：** SessionStart / resume / clear / compact 四个 hook 全部引用 `bash scripts/docs/session-begin.sh`，但脚本不存在。Claude Code 启动时 hook 执行失败，可能阻塞启动流程。

**根因：** hook 配置先于脚本创建。

**修复建议：** 创建 `scripts/docs/session-begin.sh`，实现上下文加载、STATUS.md 检查、session-start 记录三件事。**（已修复 ）**

---

### F-003 | High | `validate.sh` 调用未定义函数 `file_mod_time`

**位置：** `scripts/docs/validate.sh:98-99`

**描述：** R10 检查中调用了 `file_mod_time` 函数，但 `validate.sh` 没有 `source platform.sh`。该函数定义在 `platform.sh` 中。macOS 上 `stat` 的 BSD 语法与 GNU 不同，没有该兼容层会导致 R10 静默失效。

**根因：** 校验脚本只编排 Python 引擎，R10 的 Bash fallback 逻辑缺少跨平台依赖。

**修复建议：** 在 `validate.sh` 开头添加 `source "$(dirname "$0")/platform.sh"`。或移除依赖该函数的那段 R10 逻辑。**（已修复 ）**

---

### F-004 | High | `generate-status.py` 硬编码 `{{Project Name}}`

**位置：** `scripts/docs/generate-status.py:171`

**描述：** STATUS.md 中的项目名行写死为 `{{Project Name}}`，任何项目运行 `update-status.sh` 后看到的都是占位符，不会被实际替换。

**根因：** `generate-status.py` 没有从外部配置（如 `mkdocs.yml` 的 `site_name`）读取项目名。

**修复建议：** 改为从 `mkdocs.yml` 读取 `site_name`，或从 `scripts/docs/vars.sh` 读取。**（已修复 ）**

---

### F-005 | High | `pre-commit` 的 `CHANGED_SRC` 硬编码 `^src/`

**位置：** `scripts/docs/pre-commit:67`

**描述：** 源码变更检测逻辑硬编码了 `^src/` 前缀。通用模版的目标项目可能使用 `app/`、`lib/`、`packages/` 等不同源码目录。匹配不到则跳过 src 变更的生命周期强制约束。

**根因：** 没有为可配置的源码目录名提供变量层。

**修复建议：** 新增 `scripts/docs/config.sh`，在其中定义 `SRC_DIRS="src"`，`check-rules.py` 和 `pre-commit` 都引用此变量。`setup.sh` 安装时交互式配置。**（已修复 ）**

### F-008 | Medium | `generate-status.py` 自动运行 `npm run build`

**位置：** `scripts/docs/generate-status.py:131-141`

**描述：** 生成 STATUS.md 时自动触发 `npm run build`。非 JS 项目会报错；JS 项目每次 `update-status.sh` 都会触发完整构建（可能数十秒），而 STATUS.md 生成本应是一个快速操作。

**根因：** 将构建状态检查与状态生成耦合过紧。

**修复建议：** 默认跳过构建检查，添加 `--check-build` 可选参数触发，或读取缓存的上次构建结果。**（已修复 ）**
