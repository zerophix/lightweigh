# README 结构规范

> 适用场景：所有项目的 README.md。任何 AI 撰写或改写 README 时必须遵守本规范；
> 机读层由 GOV-README-001~005 规则族强制校验，手读层由本指南约定。

---

## 1. 设计原则

README 回答读者三问，章节按三问排序：

1. **这是什么？**（陌生人 30 秒判断）
2. **怎么跑起来？**（新人 5 分钟内可执行）
3. **往哪深入？**（协作者找到文档入口）

规范分两层，职责不同：

| 层 | 内容 | 约束方式 |
|----|------|---------|
| 机读层 | 标题层级与顺序的结构契约 | FAIL 级校验（GOV-README-001~004），阻塞提交 |
| 手读层 | 章节内容、详略、行数 | 指南约定 + WARN 提示（GOV-README-005）+ 评审把关 |

---

## 2. 机读层（结构契约，校验强制）

以下规则逐条对应校验规则族，违反任何一条即 FAIL：

### 2.1 H1 唯一且开头（GOV-README-001）

- README 的**首个非空行**必须是一级标题（`# ` 开头）。
- 全文**恰好一个 H1**，二级标题不得伪装成标题行（如 `#` 与文字之间无空格）。
- **代码围栏（```）内的 `#` 行不参与计数**——快速开始里的 shell 注释
  `# 1. 安装依赖` 是代码，不是标题（CommonMark 语义）。

```
# 项目名 —— 一句话定位     ← 第一个非空行，全文唯一的 H1
（两三行摘要）
```

### 2.2 「当前状态」固定收尾（GOV-README-002）

- 必须存在且**唯一**的 `## 当前状态` 章节。
- 它必须是**最后一个二级章节**——之后不得再出现任何 `## ` 章节。
  状态区是 AI 接力的握手区，放中间会被后续章节稀释。

### 2.3 「反思」是状态节第一个子节（GOV-README-003）

- `## 当前状态` 之下第一个三级子节必须是 `### 反思`。
- 项目快照、工程规模、AI 交接等自动段落一律排在反思**之后**。
- 反思内容的非空、长度、新鲜度由 R0 规则另行强制（本规范不重复定义）。

### 2.4 「快速开始」的顺序位置（GOV-README-004）

- 若存在 `## 快速开始`，必须**先于**以下章节出现：`## 目录结构`、`## 架构`、`## 核心功能`。
- 若不存在 `## 快速开始`，输出 WARN 建议补充（不阻塞）。

### 2.5 「相关文档」入口（GOV-README-005，WARN）

- 建议提供 `## 相关文档` 作为深入阅读入口；缺失时输出 WARN，不阻塞提交。

---

## 3. 手读层（标准大纲，指南约定）

机读层之下，推荐按以下大纲组织（`←` 注释为详略要求）：

```markdown
# 项目名 —— 一句话定位
（两三行摘要：做什么、给谁用）

## 快速开始            ← 从零到跑通的最少命令，可复制执行，控制在 20 行内
## 目录结构            ← 只解释顶层目录 + 有认知成本的目录，逐文件罗列应拆到 docs/
## 核心功能 / 架构      ← 应用类项目讲架构与管线；工具类项目讲子系统
## 相关文档            ← 深入阅读入口（docs/、DEC 索引、API 参考）

## 当前状态            ← 【机读层强制：必须是最后一个二级章节】
### 反思               ← 【机读层强制：第一个三级子节】
### 项目快照 / 工程规模  （可选，自动生成，排在反思之后）
```

### 3.1 长度分级

| 项目类型 | 建议行数 | 依据 |
|---------|---------|------|
| 模板 / 脚手架 | ≤150 行 | 读者是评估者，84 行的模板 README 是基准样板 |
| 应用 / 平台 | ≤400 行 | 允许详尽；超过则把目录结构、API 细节拆到 `docs/` 留链接 |

### 3.2 自动生成段落规则

- 由脚本写入的段落（项目快照、工程规模、最新决策）必须**标注来源**，人工不得手改——
  下次生成会覆盖。这类内容的明细归 STATUS.md，README 只留给人看的结论。
- 状态节之外的章节一律人工维护。

### 3.3 反例对照（来自 alpha-studio 实测）

| 反例 | 违反规则 | 修正 |
|------|---------|------|
| `### 反思` 前面排了项目快照/工程规模 | 003 | 反思提到第一位 |
| `## 当前状态` 之后又开 `## AI 协作`、`## 相关文档` | 002 | 移到当前状态之前 |
| 目录结构节 75 行逐文件罗列 | 手读层 | 拆到 docs/reference/ 留链接 |
| `## 当前管线瓶颈` 作为独立顶层节（易过期） | 手读层 | 并入「当前状态」由生成器维护 |

## 5. 维护约定

- 修改本规范的机读层条款时，**同一提交**内必须同步修改：校验实现、映射表、
  负向测试（先测试后实现，见 DEC-006）。
- 规范新增强制条款前先回答治理五问：检测时机、执行介质、可测试性、盲点、
  与生产环境的差距——答不全的条款只能作为 WARN 或删除。
