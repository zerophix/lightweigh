## 1. 背景与目标

### 1.1 背景

`lightweigh`（品牌名 **轻衡**；原仓名 qk-health-v2）Figma 设计稿现有 10 个移动端页面，覆盖健康概览、身体成分、趋势、设备、AI 助手等核心场景，但**缺少登录/注册与首次登录引导页面**。

本次任务：为 App 增加登录体系（手机号、账号密码、微信、邮箱、访客 5 种方式），并在首次登录后引导用户填写年龄、性别、身高作为用户元数据。

### 1.2 目标

1. 提炼现有 10 页的**统一设计体系**（Design Token + 组件规范），作为后续一切原型与开发的唯一视觉基准。
2. 基于该体系设计**登录 8 屏原型**，确保新页面与现有页面风格完全一致。
3. **原型先行**：原型风格统一确认后，才进入开发阶段。

### 1.3 方法与资产

- 通过 Figma REST API 拉取完整节点数据（`/v1/files/:key`，970KB），脚本遍历全部节点统计颜色/字体/圆角/间距/阴影的实际使用频次。
- 通过 `/v1/images` 导出 10 页 @2x 高清渲染图（804px 宽）存入 `design/prototypes/`。
- 视觉核对：已逐张核对首页、AI 授权页、趋势页、AI 对话页 4 张代表图，与 JSON 统计完全吻合。

## 2. 设计基调

**低饱和健康绿 · 无阴影色彩分层 · 大圆角亲和感 · 双字体分工**

三条核心原则：

1. **不用阴影分层**：全文件仅 1 处 drop shadow。层级完全靠背景色四级递进实现：页面底 `#F6F8F5` → 白卡 `#FFFFFF` → 浅绿卡 `#E4F2EB` → 主按钮 `#258C77`。
2. **文字不用纯黑**：正文与标题一律用深墨绿 `#203D37`，视觉柔和。
3. **文案有温度、有边界**：产品语「轻一点，更懂自己」；每页底部固定 10px 免责文字（`#80918B`），医疗/健康合规意识强。

### 3.2 字体（双字体系统）

| 字体 | 用途 | 规格 |
|------|------|------|
| **Noto Sans SC** | 中文（绝对主力） | 9/10/11/12/13/14/16/21/22/24px，字重 400/500/700 |
| **Inter** | 数字、时间 | 9px(图表)、14px w600(状态栏时间)、27px w500(卡片大数值)、大数值展示态可达 ~64px |

字号阶梯（按重要性）：

- 页面大标题：**21–24px w700**（`#203D37`）
- 卡片大标语：**22px w700**
- 分区/卡片标题：**16px w700**
- 列表项标题：**13px w500**
- 正文：**12–13px w400**
- 辅助/免责/时间戳：**10px w400**（`#80918B`）
- 图表刻度：**Inter 9px w400**（`#80918B`）
- 大数值：**Inter 27px w500**（卡片内）/ 展示态更大

行高规律 ≈ 字号 × 1.2（如 10→12、11→13、12→14、13→16、14→17、16→19、21→25）。字距 0。

## 6. 登录原型规范（8 屏）

### 6.1 交互流程

```
[1 登录主页]
  ├─ 手机号登录 ──→ [2 手机号+验证码] ──┐
  ├─ 账号密码登录 → [3 账号密码] ──────┤
  ├─ 邮箱登录 ────→ [4 邮箱登录] ──────┤
  ├─ 微信登录 ────→ [5 微信授权确认] ──┤
  └─ 访客体验 ────→ [6 访客模式确认] ──┤（访客直接进首页，跳过引导）
                                        │
              首次登录（资料不全）←──────┘
                    ├─→ [7 引导·年龄性别]
                    └─→ [8 引导·身高] ──→ 进入首页
```

- 手机号/账号密码/邮箱/微信：登录成功后若元数据缺失 → 进入引导 7→8。
- 访客：登录页提供「先逛逛」入口，直接进首页，不进引导（元数据后可在「我的」补填）。

### 6.2 通用规范（所有登录屏）

- 背景 `#F6F8F5`，左右边距 22，内容区 358。
- 顶部：品牌区（叶子 logo + 「轻衡」）或返回导航（21px w700 标题）。
- 大标语 24px w700 `#203D37`；副标语 12px `#5D756D`。
- 输入框/按钮/标签全部套用第 4 节规范。
- 底部固定：协议文字（10px `#80918B`）「登录即代表同意《用户协议》与《隐私政策》」，协议名主色可点。
- **无阴影**，靠色层分层。

### 6.3 逐屏设计

**屏 1 · 登录主页**
- 品牌区（叶子 logo + 轻衡）+ 大标语「欢迎回来，轻一点更懂自己」+ 副标语。
- 白卡列表（r16）承载 4 个主登录入口，每行：圆形图标底衬 + 标题 + 副文 + chevron：
  - 手机号登录（推荐，主色高亮「快捷」标签）
  - 微信登录（微信绿图标点缀）
  - 邮箱登录
  - 账号密码登录
- 主按钮「手机号登录」（最常用，直接提为底部主 CTA）。
- 底部：「访客体验 ›」文字入口（11px `#80918B` 居中）。
- 协议文字。

**屏 2 · 手机号登录**
- 返回导航「手机号登录」。
- 标语「输入手机号」+ 副标「未注册的号码将自动创建账号」。
- 输入框（手机号，+86 前缀）→ 验证码输入框 + 「获取验证码」文字按钮（倒计时态）。
- 主按钮「登录 / 注册」。
- 其他方式登录链接（返回屏 1）。

**屏 3 · 账号密码登录**
- 返回导航「账号密码登录」。
- 输入框「用户名 / 手机号 / 邮箱」+ 密码框（右侧显示/隐藏切换）。
- 「忘记密码？」主色链接（右对齐）。
- 主按钮「登录」。

**屏 4 · 邮箱登录**
- 返回导航「邮箱登录」。
- 输入框「邮箱地址」+ 密码框 或 「发送验证邮件」文字按钮。
- 主按钮「登录」。

**屏 5 · 微信授权确认**
- 居中：微信圆形图标（大）+ 标语「使用微信账号登录」+ 副标「轻衡将获得你的微信昵称与头像」。
- 白卡列出将获取的信息（昵称/头像/ openid，圆形图标底衬行）。
- 主按钮「微信授权登录」+ 次按钮「使用其他方式」。

**屏 6 · 访客模式确认**
- 居中图标 + 标语「先逛逛，不用登录」+ 副标「访客模式下数据仅保存在本机，更换设备将丢失」。
- 白卡说明访客限制（不能同步/不能连设备/数据本机）。
- 主按钮「进入体验」+ 次按钮「返回登录」。

**屏 7 · 首次引导 · 年龄性别**
- 顶部进度指示（3 步中的第 1 步，参考分段/进度条样式）。
- 大圆形图标 + 标语「完善资料，让参考更适合你」+ 副标「用于计算 BMI、体脂率参考区间」。
- 白卡表单：年龄输入框（数字）+ 性别分段控件（男 / 女 / 不告知，复用 4.6 分段样式）。
- 主按钮「下一步」。

**屏 8 · 首次引导 · 身高**
- 进度指示（第 2/3 步）。
- 标语「你的身高是多少？」+ 副标「用于身体成分计算」。
- 白卡：身高输入（cm，大数值 Inter 展示 + 单位）+ 可选滑动微调。
- 主按钮「完成，开始使用」+ 次按钮「跳过」（元数据可后补）。

### 6.4 元数据模型（对齐现有用户聚合）

引导收集的字段需与现有 `Member`/用户聚合及首页、AI 对话页展示一致（对话页已展示「女 · 30岁 · 168 cm」）：

| 字段 | 类型 | 来源屏 | 说明 |
|------|------|--------|------|
| 年龄 age | Int | 屏 7 | 或由出生日期推导 |
| 性别 gender | Enum(MALE/FEMALE/UNSPECIFIED) | 屏 7 | 不告知 → UNSPECIFIED，影响体脂率参考区间 |
| 身高 heightCm | Int | 屏 8 | 用于 BMI/体脂计算 |

> 开发时需核对 `domain` 现有用户/成员聚合字段命名，保持一致，避免新增平行字段。
