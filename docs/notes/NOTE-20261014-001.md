# 四个潜伏缺陷的同日发现：证据驱动的治理模板实战复盘

> **来源:** AI-DISCUSSION
> **日期:** 2026-10-14
> **状态:** 活跃
> **相关决策:** DEC-004, DEC-005, DEC-006, DEC-007, DEC-008

---

## 背景

本模板的核心声称是"规范必须配上可执行校验，否则必然漂移"。但 2026-10-14
一天之内，这套自称带门禁的校验体系在首次真实执行路径上连续暴露 4 个潜伏
缺陷——此前它们全部处于"本地全绿"状态。本笔记复盘发现过程，作为
"为什么模板需要负向测试与真实执行验证"的实证案例。

## 四个缺陷

### 1. DEC-004：R0 反思复用检测在干净树上 100% 误报

- **现象**：仓库首次配置远程执行 push，pre-push 校验全部通过仍拒绝推送
- **根因**：复用检测固定比对工作区与 HEAD——只在 pre-commit 时机成立；
  提交落地后工作区必然等于 HEAD，pre-push/CI 场景下检测 100% 误报
- **发现方式**：首次真实 push 被钩子拦截（仓库此前无远程，钩子从未真正跑过）
- **修复**：比对基线随执行环境分流（脏比 HEAD、净比 HEAD~1），2 个回归用例

### 2. DEC-005：pre-push 通过条件引用了校验器永不输出的字符串

- **现象**：修复 1 后校验全绿，push 仍被拒且不打印任何 FAIL 明细
- **根因**：pre-push 用 `grep "违规: 0"` 判定通过，但 Python 校验引擎成功
  路径只输出"全部通过"——该字符串在成功输出中不存在，**pre-push 永远不会
  放行**；同族缺陷：metrics 消费同一字符串，「校验违规」指标恒为 ?
- **发现方式**：矛盾输出（全绿 + 拒绝）逼出的追查
- **修复**：摘要行恒定输出 + pre-push 改退出码判定 + 子进程契约测试

### 3. DEC-007：进程内 pytest 夹具吞掉校验现场

- **现象**：新规则打印了 `[FAIL]`，摘要却是 `违规: 0 项`——两个数字同时为真
- **根因**：`pytest.main()` 进程内执行测试，负向测试夹具每用例后
  `core.errors.clear()`，把 pytest 阶段之前累积的全部违规清零——
  **全量模式（CI 正是这种）下早期规则长期假阴性**
- **发现方式**：自相矛盾的输出（FAIL 与 0 并存）
- **修复**：夹具改快照-恢复语义 + 元测试锁死

### 4. DEC-008：R0 两处检查在干净 checkout 上必然失败

- **现象**：干净克隆模拟 CI，第一跑报「未找到 handoff 反思记录」，
  且该 `fail; return` 还掩盖着第二处必然失败「Git hooks 未安装」
- **根因**：记忆文件不入库、hooks 不随 clone 走——任何干净检出天然缺失，
  不修则 Actions 一旦跑通也永久红灯
- **发现方式**：git clone 干净副本实测（新校验上线前的标准动作）
- **修复**：文件缺失跳过（对齐 GOV-CONTENT-008 先例）+ CI 环境跳过 hooks，
  4 个分流测试锁双向语义

## 共同病根

四个缺陷同族：**规则写完之后，没有任何东西盯着它在真实执行路径上是否成立**。

| 缺陷 | 被跳过的"真实执行路径" |
|------|----------------------|
| 1 | 从未有过远程 → pre-push 从未执行 |
| 2 | 从未有过远程 → pre-push 从未执行 |
| 3 | 早期校验全绿 → 夹具清零从未被观测到 |
| 4 | 从未在干净 clone 上跑过 validate |

本地全绿只证明校验认识你的机器；"装了钩子"不等于"钩子在真实场景工作过"。

## 方法论沉淀

1. **新钩子/新校验上线前，在 `git clone` 出来的干净副本上跑一遍**——
   本地工作树是特例，干净 checkout 才是 CI 和新用户的真实起点
2. **自相矛盾的输出是状态被中途篡改的直接证据**（FAIL + 违规 0、全绿 + 被拒），
   见到任何一组互相打脸的输出，不信任何一边，追查中间环节
3. **`fail; return` 会吞掉连锁失败**——修第一处时把同函数后续检查手动过一遍
4. **从未在真实场景执行过的钩子不视为已验证**——写进 DevNotes，与负向测试
   （规则被删时有人发现）互补：负向测试防"规则失效"，真实执行防"路径失效"

## 对外叙事价值

这四个案例恰好构成模板与市面静态模板的差异化证据：静态提示词模板的缺陷
只能被使用者偶然撞见，且无人留下根因记录；本模板的门禁不仅拦下了问题，
每个缺陷都以 DEC 形式留下现象-根因-修复-测试的完整链条，修复即回归用例。
**缺陷被抓住的过程本身，就是治理系统在工作的证明。**
