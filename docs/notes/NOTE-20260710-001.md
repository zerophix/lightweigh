# NOTE-20260710-001: AI 接力协作分析 — 从虚假设计到闭环实现

> Harness 零信任验证驱动的一次深度反思：接力到底能不能用？

---

## 背景

模板 v1.0.0 实现了任务看板（`.ai/tasks.json`）、AI 收件箱（`docs/ai/inbox/`）和
session 收尾脚本（`session-end.sh`）。随后自问：这些东西真的能让 AI 接力吗？

## Harness 验证结论

用 Harness 三条铁律检验接力设计发现：

| 声称 | 验证结果 | 问题 |
|------|---------|------|
| 数据持久化 | 真 | tasks.json 和收件箱文件跨 session 存在 |
| 新 AI 能读到 | 真 | AGENTS.md 启动协议指定了读取路径 |
| 结构化交接 | 真 | session-end.sh 产出格式化 markdown |
| 新 AI 会接着干 | 假 | 新 AI 是全新实例，无记忆、无义务 |
| 任务板驱动工作 | 假 | 人类 prompt 决定 AI 做什么，不是任务板 |
| 交接有强制力 | 假 | session-end.sh 不跑也没人知道 |
| 闭环可验证 | 假 | Session B 做完后无人核实完成了啥 |

**核心矛盾：数据是接力的，但 AI 不是。**

磁盘上留下了接力信，但下个 AI 是全新的 Claude 实例。它读到 AGENTS.md 说
去查收件箱，但它失去了之前 session 的推理过程和对话上下文。

## 虚假设计的根源

### 1. 数据持久不等于状态延续

```
Session A 状态                    Session B 状态
  - 对话历史                       - 空的
  - 推理过程（为什么选 JWT）        - 只读到"选了 JWT"
  - 看过哪些代码                   - 从头读起
  - 踩过哪些坑（已知+未知）         - 可能重踩
  - T-001 的上下文                 - T-001 只是个标题
```

### 2. 人类才是真正的接力员

```
Session A 结束 → AI 不会自动启动下班 session
                → 收件箱不会主动通知任何人
                → 人类第二天打开电脑启动 Claude Code
                → 人类输入 prompt 决定 AI 做什么
                → AI 不能反驳人类
```

### 3. 没有强制力

所有接力机制都是建议性的，没有一个能强制执行。

### 4. 没有闭环验证

```
Session A 留信 → Session B 读信 → B 标记已读
                                    ↓
                    Session B 做没做？对不对？
                    如果有歧义能问 A 吗？不能
```

## 闭环设计

### 核心思路

人类是接力枢纽，AI 不能跳过接力步骤。

```
Session A 结束
    │
    ├── session-end.sh: 4 项强制交接
    │   (完成 + 未完成 + 决策理由 + 风险 + next_why)
    │
    ▼
Session B 启动（session-begin.sh 自动触发）
    │
    ├── 显示未读消息数 + next_action + 确认状态
    ├── AI 必须问人类：上一个计划做 X，要继续吗？
    │
    ▼
人类确认或否决
    │
    ├── 确认 → task-board.sh confirm → 接着干
    └── 否决 → 人类指定新方向
    │
    ▼
Session B 工作 → session-end.sh → Session C
```

### 已实现的闭环组件

| 组件 | 文件 | 职责 |
|------|------|------|
| 任务看板 + why 字段 | task-board.sh | 每个任务和 next 附带理由 |
| confirm 命令 | task-board.sh confirm | 人类显式确认方向，标记 confirmed |
| 启动强制读信 | session-begin.sh | 显示未读消息 + next 状态 + 进行中任务 |
| 结构化交接 | session-end.sh | 4 项必填交接 + 推理过程 |
| 接力铁律 | AGENTS.md | 3 条必须做 + 4 条不能违反 |

### 从 v1 到闭环的改进

```
v1 接力:   写信 → 读信 → 自由发挥
闭环接力:  写信(含why) → 读信 → 人类确认方向 → 干 → 4项交接(含why)
```

## 剩余缺口

| 缺口 | 难度 | 说明 |
|------|------|------|
| AI 自动读信 | 简单 | session-begin.sh 已输出提示，但 AI 需主动执行 inbox.sh read |
| reasoning trace | 困难 | 需要把 AI 的思维过程结构化存下来 |
| 完成度验证 | 中等 | Session B 做完后需逐项核对 T-xxx 是否真的完成 |
| 防静默跳过 | 中等 | session-begin.sh 可增加强制读信逻辑 |
| 自动状态推送 | 困难 | 收件箱不会主动通知，需人类手动启动 Claude Code |
