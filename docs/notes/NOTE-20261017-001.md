> **来源:** AI-DISCUSSION

## 背景

对照参考项目 `qk-health-android` 与当前项目 `lightweigh`（原仓名 qk-health-v2），逐项核对业务功能是否已全部移植。
参考项目业务源码位于 `qk-health-android/app/src/main/java/com/example/bodyfatscale/`，共 30 个业务类；
当前项目为四模块分层架构（domain/application/infrastructure/app），11 个 feature 各按四件套收敛。

## 结论

**参考项目功能已全部移植到当前 v2，没有业务遗漏。**
且当前 v2 在架构（四模块分层 + 端口隔离 + 四件套）与视觉（设计 token + 组件系统）上均优于参考项目。
唯一差别是参考项目为单模块 + Java 混合扁平结构，v2 为多模块分层重构——这是有意的架构升级，非功能缺失。

## v2 超越参考项目的点

1. **腰围指标**：参考项目为独立腰围卡，v2 并入体重卡三指标格（更聚合）。
2. **设计系统**：v2 用 QkCard/QkAreaChart/QkProgress/QkBodyBar/QkWheelPicker 全套组件，参考项目大量硬编码颜色。
3. **分层可测性**：application 读模型（HomeGoalState/TrendQuery）纯 JVM 可单测，参考项目 UI 层直接触存储。
4. **首页面积图**：QkAreaChart 组件被复用接入 WeekTrendCard，是自研可视化组件（非参考项目 MiniChart 直绘）。

## 本次会话的关联改动

- 新增 `ui/components/QkAreaChart.kt`：面积趋势图组件（折线 + 面积填充 + 端点圆点，QkColor token）。

- `DeviceScreen.kt`：修复 `rememberLauncherForActivityResult` 泛型推断（显式指定 `<ScanOptions, ScanIntentResult>`）。
