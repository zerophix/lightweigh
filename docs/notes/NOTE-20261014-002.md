# 模板分叉体检：web-ai-bridge 兼容性验证与升级路径缺口

> **来源:** PORTING-VALIDATION
> **日期:** 2026-10-14
> **状态:** 活跃
> **相关决策:** DEC-004, DEC-005, DEC-007, DEC-008（上游修复侧）

## 背景与场景修正

T-003 原计划把模板移植到"陌生真实项目"。选定 web-ai-bridge 后发现场景修正：
它不是移植空白区，而是**同一模板家族的兄弟分叉**——同款 AGENTS.md/钩子/
DEC 格式/任务板/收件箱，且自行扩展了 policy 引擎系脚本。于是本次验证改为
**分叉兼容性体检**：一个 7 月从模板分出去的分支，在 10 月的真实状态如何。

## 体检结果（2026-10-14 实测）

### 腐化数据

| 指标 | 实测值 |
|------|--------|
| 累积违规 | **131+ 项**（校验器自报「...及其他 127 项违规」） |
| 指标/记忆新鲜度 | 停滞 41 天（GOV-CONTENT-002/009 FAIL） |
| session-end 间隔 | 1342 小时（GOV-PROTO-002 FAIL） |
| 收件箱未读 | 2 封超时未读（GOV-PROTO-001 FAIL） |
| DEC-217 | 未填充的模板占位文件（`<第 1 步待办>`），且未提交入库 |

### 分叉携带的上游旧缺陷（修复不传播的直接证据）

1. **GOV-PROTO-001 仍是 pre-DEC-002 版**：文案「超 48 小时视为协议违规」，
   实现仍是任何未读即 FAIL——与上游已修复语义不一致
2. **无 DEC-004 修复**：grep 无 porcelain/HEAD~1 逻辑，干净树复用检测缺陷仍在
3. **无 DEC-005 修复**：输出契约旧格式
4. **无 DEC-008 适配**：干净 checkout 上必然红

### 分叉自有的新摩擦

- **GOV-TEST-GOV-004 大面积 FAIL「python 不存在」**：其测试依赖检查假定
  `python` 命令存在（conda quant 环境），系统 python3 下 15+ 个测试文件全部
  报依赖缺失——校验器的环境假设没有跨环境兜底

## 摩擦点归类（对模板的改进输入）

| # | 摩擦 | 根因 | 模板侧改进建议 |
|---|------|------|---------------|
| 1 | 分叉携带旧缺陷，修复不传播 | **模板没有版本号与升级机制** | 引入模板版本标记 + `gov-upgrade.sh`（对比上游脚本 diff，选择性同步） |
| 2 | 腐化 41 天后校验墙式变红，被整体弃用 | 时效类规则（30 天新鲜度）对停摆项目没有宽限模式 | 增加「停摆检测」：项目停摆 N 天后时效类降级为 WARN，恢复活跃后自动恢复 FAIL |
| 3 | DEC-217 占位未填充入库 | session 中断留下半成品，无「孤儿占位检测」 | GOV-CONTENT 增加：含 `<` 占位符的 DEC 拒绝入库 + 超期未提交占位报警 |
| 4 | `python`/`python3` 环境假设 | 校验器直接调用解释器名 | 统一走 `sys.executable` 或 python3 探测兜底 |
| 5 | 钩子很少触发（backend 提交不触发 validate） | pre-commit 只在 docs/scripts 变更时跑 validate | 可接受（Q1 时机窗口的有意设计），但意味着**规则存在 ≠ 规则被经过**——与上游 DEC-004/005 教训同构 |

## 核心结论

**模板当前最大的战略缺口是升级路径。** 分叉的宿命是：上游修了缺陷它不知道、
上游加了规则它没享受到、它自己长的扩展（policy 引擎系）上游看不见——三方
发散只能靠人工逐文件对比收敛。alpha-studio（276 DEC、停摆 4 周）大概率
处于同样的分叉腐化曲线，只是体量更大、腐化更慢被掩盖。

验证类任务的可复用做法：**体检既有用户比安装新用户信息量大**——新用户跑通
只证明安装脚本能跑，既有分叉的真实状态才暴露模板的生命周期缺陷（腐化、
升级、孤儿文件、环境假设）。

## 对 T-003 的结论

- 未向 web-ai-bridge 写入任何文件（其工作区有进行中的未提交工作，且治理
  属于该项目自身的决策范围）
- 分叉体检即移植验证的替代交付：模板的"安装面"无摩擦，"生命周期面"暴露
  上述 5 个改进点，其中升级路径（#1）为 P0 战略项
- 建议的后续：模板版本化 + gov-upgrade.sh 作为下一个迭代主题
